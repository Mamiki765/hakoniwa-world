## 3. 今回の実装案

以下の細則は、会話で出た案を実装可能に整理したもの。Ownerが一語ずつ指定した事実ではない。本書を指定した開始プロンプトでは、この実装案で進める。未確定の将来設計を理由に、決まった第一弾全体を止めない。

### 3.1 一つの倍率とrating基準

```text
S(L) = 1.1 ^ (max(0, L - 200) / 10)
W = S(武器IL)
A = S(防具IL)
基準IL = max(200, min(武器IL, 防具IL))
必要値倍率 = S(基準IL)
```

防具未装備は倍率1・基準200相当として扱う。区間内のILにも同じ式を使い、10IL刻みに切り捨てて段差を新設しない。S(200)=1、S(210)=1.1、S(220)=1.21は式の説明であり、全IL表をテストへ複製する指示ではない。

- 基準世代では100rating=1 percentage pointを換算単位にする。既存bpsと同じ数値を基準ratingとして利用できる。
- 新規品の対象エンチャは、旧式の同じ品質rollを基準に`rating = 基準roll × S(その装備のIL)`とする。旧式の通常OP倍率はIL101で、共鳴の割合rollはIL200で上限になるが、その**基準rollに対する世代成長**を追加する。乱数を余分に引いて品質を変えない。
- 旧品も保存済みの実rollを基準値として現行ratingへ投影する。同じ品が旧generator由来か新generator由来かだけで現行効果が変わらないようにする。旧payload/identityそのものを新生成し直さない。
- 同系ratingは集計後に必要値倍率で割り、従来の実効bpsへ解決する。ratingを加えたうえで旧bpsも残す二重計上をしない。固定効果は由来を分ける。
- 武器210/防具210/アクセ220なら、同rollのアクセ効果は`1.21/1.1=1.1`倍。武器・防具まで220なら同世代の実効水準へ戻る。これはエンチャの増加率であり、総DPSの増加率ではない。
- IL210バハ石も同じ解決を使う。対象ratingは基準roll×1.1、実効補正はそのratingを必要値倍率で割る。したがって基準IL200なら基準roll比×1.1、基準IL210なら×1.0（丸め・cap前）。石の装備中に最終ダメージへ別途×1.1を加える意味ではなく、共通処理とは別の石専用倍率を重ねない。
- 丸めは現行の整数/bps契約に合わせ、同一入力から同一結果になる小さな共通処理で行う。表示だけ独自式で再計算しない。全DBのfloat化・BigInt化は別件。

### 3.2 出力倍率は一度だけ

| 対象 | 今回の適用案 |
|---|---|
| 通常攻撃、技、独立した反撃・追撃等の固定値/能力値由来の攻撃出力 | 使用者の武器倍率W。既存の能力値・weapon power・技倍率の関係を残し、絶対値の成分へ一度反映する。 |
| 固定量/能力値由来の回復・障壁 | 術者の武器倍率W。攻撃と同じ世代進行を持たせる。 |
| 最大HP | 既存計算後の最大HPへ防具倍率Aを一度反映する。防御値まで同時にA倍して耐久へ重複した世代成長を足さない。 |
| 最大HP比例の回復/障壁等 | 倍率反映後の参照HPを用いる。そこへ同じ世代倍率をもう一度掛けない。 |
| 実ダメージを元にした吸収等 | 倍率反映済みの実ダメージから計算する。回復倍率でさらに二乗しない。 |
| 継続効果など成分が混在するもの | 参照するHP割合・能力値由来成分/上限を区別し、一度だけ反映する。名前だけで全部W倍にしない。 |

HP再計算・覚醒・装備交換・貸出への接続を既存の共通経路で揃える。現在HPについては既存の回復/上限補正契約を優先し、着脱で新しい回復報酬を作らない。

旧装備の内部加算値は保持。IL211〜220の素体生成は既存補間/外挿を利用し、別の加速カーブを作らない。通常生成の対応上限を220まで延長しても、狩場未実装のうちは勝手に新ドロップ先を開かない。

NPCは実際の定義を維持し、案内人・グラムのフレーバーIL1254へこの成長式を自動適用しない。「NPC数値を変えない」と「新装備でも旧勝率が全く同じ」は区別する。

### 3.3 rating対象とcapの境界

- 通常エンチャ：`physical_damage_bps`、`miracle_damage_bps`、`healing_bps`、`barrier_bps`、`critical_chance_bps`、`critical_damage_bps`、`mp_cost_reduction_bps`。
- 共鳴のランダムaffix：単体/範囲/通常/攻撃技強化、単体/範囲回復強化、および防御行動強化。アクセと同じ共通IL倍率でrating化し、武器/防具の必要値倍率で換算する。中級1結晶はIL210維持・対象rating×1.1がOwner確定。基礎能力と保存品質を保持する。
- エクスカリバーの物理・魔法・治癒・MP補正も同じ表示/解決へ寄せる。自然回復2%は固定のまま。
- 共鳴の固有効果`unique_effect`（黒竜の共鳴）は今回は固定%として保持する実装案。ランダムaffixと同じtargetへ合算されることがあるため、固定分まで誤ってrating化/二重計上しない。
- 防御行動強化など減算型エンチャは、同系統の実効補正を合算してから90%以下にし、`1-軽減率`へ入れる。各装備を個別90%にして合計が100%を超える処理にしない。
- この90%は新しいエンチャ解決側の上限として実装する案。既存の通常防御/guardの合成75%上限、覚醒・かばう等を一括90%へ置き換える指示ではない。最終合成軽減率を全状況で90%に統一する指示とも扱わない。
- 既存のクリ率60%・MP軽減40%は別指定まで維持。攻撃/回復等へ新しい共通capを追加しない。障壁の現行容量上限などもこのために勝手に廃止しない。

### 3.4 研磨は表示移行と強化量の変更を分ける

現行は固定能力に+0時の30%を1段階ごとに加算、割合効果に0.1 percentage pointを加算する。本件ではまず**この既存強化量・費用・+5上限を保って、対象affixの増加をratingと実効%で表示**する。固有固定%部分は固定%のまま。

Ownerの「そら×1.1じゃないの()」は、この会話では直後のAssistantがアクセのIL差として回答している。研磨1段階の実効果を一律1.1倍へ変える指示だと確定できないため、それを黙って採用しない。研磨の量的再設計は残件として短く報告し、装備倍率/ratingの実装全体は進める。過去のAssistantの見本数値も新たな強化仕様の根拠にしない。

### 移行・versioning

1. 保存済み装備の基礎値/affix/品質/研磨、所持・装備状態を保持する。旧payloadはversion付きの明示的な投影を優先し、全件再抽選やidentityのすり替えをしない。原本保持が不可能な箇所だけ、理由を示して最小のforward migrationを作る。
2. 現行計算への読替えは一箇所へ寄せ、cacheと新規戦闘snapshotの規則identityも更新する。表示だけratingで戦闘は旧bps、あるいはその逆にしない。
3. production使用済みのfoundation/trial manifestを上書きしない。内容の意味が変わるcurrent manifestを新世代へ進める。対象Trialのcontent identityとactive runの扱いはUG-03の既存契約に従う。別Trialやapplication versionが変わっただけで全履歴をresetする処理を作らない。
4. 過去の完了結果・再送で固定された結果・報酬は再計算しない。進行・初回報酬・SP・G・装備を消さない。supported upgradeだけを対象にし、未使用の全歴史を並列engineとして抱えない。
5. 地上Rulesetは無関係なら変更しない。一つの未release変更の手直しごとにmanifest世代を増殖させない。

- 最初に現在のbranch差分・AGENTS・実行環境を確認し、上記の出力/集計点へ実装する。作業中の別worktreeやコンテナを止めたり未commit変更を捨てたりしない。

- 代表的な所有装備/貸出/upgradeの既存テストを必要分だけ拡張・置換する。追加ごとに「到達可能な故障」「既存代表で不足する理由」を説明できるものだけ。全IL×全職×全rarity×全seedを恒久化しない。数値調査は一時出力でよい。

- 小変更ごとの全CI、localでCIと同じ全PHPUnitの重複実行はしない。完成と資料整理をまとめてcommit/pushし、通常のPRを作成または更新する。最終runtime HEADは`[skip ci]`を使わず既存Qualityの結果を確認する。再実行は実失敗・変更・具体的な未解消懸念がある場合だけ。
