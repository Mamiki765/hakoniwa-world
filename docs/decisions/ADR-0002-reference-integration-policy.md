# ADR-0002 参考実装の統合方針

- 状態: 採用
- 日付: 2026-07-26
- 対象: 箱庭諸島2＋、やまにてぃ、新作hakoniwa-world

## 文脈

箱庭諸島2＋は、60×60の共通世界、領土・国境、ターン制処理という新作のゲーム性に近い。一方、C製CGI、固定長ファイル、順位依存所有者、固定配列など、現代的な運用に適さない制約を持つ。

やまにてぃはLaravel、Vue、Eloquent、DB transaction、クラス化したTerrainやLogなど、現代的な構成を持つ。一方、国家ごとに独立した15×15マップであり、JSONスナップショット、全島一括ターン処理、表示断片ログなど、新作の共有・動的世界には適さない設計も含む。

また、両参考物は第三者著作物であり、特にやまにてぃはリポジトリ直下の包括的なLICENSEが確認できず、依存定義のMIT表記を作品全体の許諾と解釈できない。文章、固有表現、実装、出典不明素材のコピーは避ける必要がある。一方、箱庭諸島2＋の原GIFは、作者・原配布元を明示し、Git外から非商用ゲームの実行時に使用するという個別方針が追加された。

## 決定

新作は両参考実装をコード統合しない。次の二段階で独立実装する。

1. 観察可能な挙動、データ上の意味、処理順、制約を出典付き文書へ抽出する。
2. 新作要件からドメイン仕様、ADR、テストケースを作り、その仕様に対して新規コードを書く。

箱庭諸島2＋からは共有世界というゲーム上の核を参考にする。やまにてぃからはLaravel/Vueによる責務分割の方向性を参考にする。どちらのソースも逐語変換せず、ファイル構造、class名、HTML断片、文言、数値表をコピーしない。

箱庭諸島2＋の原GIFだけは素材境界を別に扱う。画像バイナリをリポジトリへコピーせず、原名・原形式の外部ファイルをread-only mountし、Git管理する論理`asset_key`とmanifestで参照する。これはコード統合や新作独自素材としての再配布を許す決定ではない。やまにてぃの画像や出典不明画像にはこの例外を広げない。

## 採用する概念

### 箱庭諸島2＋から

- 複数国家が同じ地上マップを共有すること。
- 六角隣接に基づく領土・国境・攻撃。
- 命令キューとターンフェーズ。
- 収支、人口、施設、災害、怪獣、ミサイルが相互作用すること。
- ログとバックアップが運用上必要であること。

### やまにてぃから

- Web interfaceとターンApplication Serviceを分けること。
- Laravel、DB transaction、Entityや値オブジェクトの活用。
- Vue等による対話的なマップ操作。
- 国内命令と他国向け命令、ログ可視性を明示する考え方。
- 開発・実行環境を再現可能にする方向性。

これらはアイデアや要件として再定義し、具体表現は新規に作る。

## 採用しないもの

- CソースからPHPへの直接翻訳。
- 順位番号を所有者IDにする方式。
- 5桁16進セル、255・65535等の実装都合上限。
- 固定60×60配列または固定15×15島。
- 世界全体、島全体、毎ターン全セルを1 JSONやファイルへ保存する方式。
- ゲーム状態の全量メモリ読込みと毎ターン全走査を前提とする方式。
- HTMLやVue表示断片をログの正本にする方式。
- 平文パスワード、デバッグ認証、Webアクセス起点のターン更新。
- やまにてぃの画像、出典不明画像、文章、音、固有素材。箱庭諸島2＋の確認済み原GIFはGit外の実行時利用に限り別方針とする。

## クリーンな実装境界

- reference-analysis文書には、根拠となるファイル、関数、定数、行を記録できる。
- architecture、decisions、future-systems文書は、新作の用語と要件で記述する。
- 実装時のclass、table、APIは新作設計から命名し、参考元の構成へ機械的に対応させない。
- テストは観察したコード行を再現するのではなく、承認済みの新作仕様を検証する。
- 参考元と似る必要がある数値や文言は、由来・権利・ゲーム上の必要性を別途確認する。

## provenanceとライセンス

分析対象のリポジトリURL、commit、archive hash、読取日時を文書へ残す。参考ファイルはread-onlyとし、変更、整形、rename、commitをしない。

第三者依存のライセンスと、作品自体のライセンスを区別する。composer.jsonのlicense欄、frameworkのlicense、素材配布元の説明だけでリポジトリ全体の利用許諾を推定しない。許諾が不明ならコピーせず、必要な機能・素材を独自に制作する。

## 結果

### 利点

- 旧実装の技術的制約を新作へ固定しない。
- 共有世界と現代的Web構成を目的に合わせて統合できる。
- 出典と推測を追跡し、仕様変更をADRで管理できる。
- 著作権・ライセンス上の不用意な混入を減らせる。

### 負担

- 直接移植より初期の仕様化とテスト設計に時間が必要。
- 細部の互換性は保証されず、ゲームルールの再決定が必要。
- 参考実装に暗黙の挙動は、追加調査またはsimulationが必要。

この負担は、動的共有世界と長期拡張性を得るために受け入れる。

## 適合確認

実装レビューでは次を確認する。

- 変更がproduct配下の新規実装であること。
- reference配下を変更していないこと。
- 参考元のまとまったコード、表示文、画像バイナリがGit管理領域に含まれないこと。
- 箱庭諸島2＋の原GIF参照が`hakoniwa_original.*`の論理キーと許可済みmanifestを経由し、絶対パスをdefinitionへ持たないこと。
- 新作仕様またはADRに対応するテストがあること。
- provenance上の未解決ライセンスを「利用可」と誤記していないこと。
