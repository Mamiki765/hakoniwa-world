# マニュアルの作り方と更新の決まり

ゲーム内マニュアル（`/manual`）を書く・直す人のための手引きです。このファイル自体はマニュアルとして公開されません。

マニュアルは**遊び方の地図**です。仕様書でも攻略本でもありません。細かい数字や効果は、ゲームの画面（マスの詳細・コマンド欄・秘書画面・地底の各画面）がいちばん新しくて正確なので、マニュアルはそこへ案内します。

## 1. 載せるもの・載せないもの

### 載せる

- 遊び方の流れと、各機能が「何のためにあるか」「どこで操作するか」
- 施設・コマンドの名前、建てる場所、費用、ターンを使うかどうか、ひとことの説明（索引）
- 知らないと大きく損をする危険（例: 防衛施設に重ねると自爆、天候「終末」は巨大隕石、負けると手持ちGが半分）
- プレイヤーが判断に使う決まり（交易場の出品数・期間など）。数値は Ruleset から差し込む（3章）

### 載せない

- 確率・計算式・内部の処理順・乱数の仕組み（オーナーが載せると決めたもの＝7章を除く）
- 地底の敵の個別の能力値、ドロップの中身
- アイテムやスキルの個別の効果（画面の効果欄へ案内する）
- 特定アイテムを使った細かい仕組み
- 地底の後半の場所・物語・隠しイベント・特別な戦い
- 調整中の暫定値の細部、運営側の都合、開発の経緯
- 開発用の言葉（Ruleset、hex、turn、Nation、quantity など）

### 迷ったら

**載せずに、候補としてオーナー（リカさん）に聞く。** 「何が隠しか」はオーナーが決めます。書き手が「書いたほうが親切」と思っても、決める前に書かない。

既存の文章や、過去のマニュアルにあった記述を、オーナーの意思と思わないこと。今のマニュアルに書いてあっても、上の線引きに合わなければ消してよい。

## 3. 数値は手で書かない

版上げで数値が変わるたびにマニュアルが古くなるのを防ぐため、Ruleset にある値は差し込みで書きます。

- **索引** — 本文に `[[index:facilities]]`・`[[index:ships]]`・`[[index:commands]]`・`[[index:skills]]`・`[[index:monsters]]`・`[[index:launch-bases]]`・`[[index:typhoon]]` の段落を置くと、いまの Ruleset から名前・費用・ターン消費・ランク2の名前を読んで表を作ります。新しい施設・コマンドは、文章がなくても Ruleset の説明文で自動的に出ます
- **単独の数値** — `{{ruleset:trading_post.player.active_listing_limit}}` のように Ruleset のパスを書くと、その数値に置き換わります。見つからないときは「ゲーム画面で確認してください」と出ます。`{{ruleset:パス/100}}`（百分率に）や `{{ruleset:パス*1000}}`（規模を人数に）のように、一度だけ割る・掛けることもできます。地底の決まりは `{{underground:skip.trial.actual_clears_required}}` のように `config/underground-runtime.php` から読みます
- 手で書いてよい数値は、Ruleset に無い固定の決まり（計画30件、装備5枠など）と、例えの数字だけ。それも、無くても困らないなら書かない

## 4. 書き方

- です・ます。一文を短く。表は「何をするか」が一目で分かるときだけ
- 名前はゲーム画面の表記どおり（ボタン名・メニュー名を確かめる）
- 「〜ではありません」を重ねない。誤解されやすい一点だけ太字で書く
- 詳しい説明は書かず、画面の場所を案内する（「マスの詳細で」「効果欄で」）
- 地上の資金（億円）・輝石（Pd）・地底の輝石の欠片（G）を混ぜない

## 5. 版ごとの更新手順

### patch（x.y.Z）

誤りの修正だけ。新しい説明は足さない。

### minor（x.Y.0）

1. その版のリリース記録（`docs/releases/`）と統合PRを見て、**プレイヤーから見て増えた・変わったもの**を一覧にする
2. 新しい施設・コマンドが索引に自動で出ているか確かめ、`indexes.php` にひとことと建てる場所を書く
3. 新しい機能・仕組みについて、マニュアルにどこまで載せるかの案を作り、**書く前にオーナーに聞く**。聞き方の例:

   > 5.4.0 で増えた・変わったもの: ○○、△△、□□。
   > マニュアルの案: ○○は「何のためにあるか・どこで操作するか」まで、△△は索引のひとことだけ、□□は載せない（隠し候補）。
   > この範囲でよいですか？

4. 返事に沿って書く。消えた機能・変わった操作の記述が残っていないか、関係するページを読み直す
5. 事実の確認（今のコードと合っているか）は、ペリドット先輩に頼んでよい

### major（X.0.0）

全ページを読み直し、1章の線引きに合わない記述を消す。構成を見直すならオーナーに聞く。

## 6. 確かめ方

- `/manual` の各ページを、PC幅とスマホ幅（360px前後）、New Light と New Dark で見る
- 索引に「その他」の見出しが出ていたら、`indexes.php` に文章が無い項目がある
- `tests/Feature/FirstProductionReleaseTest.php` がマニュアルのリンク切れを見ている
