# ver 2.x roadmap

ver 2.x is the 「箱庭諸島2S＋独自システム構築期」 defined by ADR-0010. This page records sequencing boundaries, not automatic approval for every named candidate.

## 2.0.0 — Secretary v1

Approved scope:

- derived 箱庭歴 display
- one User-persistent Secretary created on first successful Nation registration
- production backfill for Users with Nation registration history only
- unnamed and one-time naming states, header entry, and Secretary page
- exactly four passive skills: 農業政策, 特産品開発, 金鉱脈調査, 最終防衛ライン
- successful-result XP, level progression, minimal production and missile effects
- attempt-start batch loading and transactional XP updates
- immutable ruleset v7 and a forward-only production migration
- focused API, UI, tests, decision records, and operator-facing migration evidence

The detailed contract is [ADR-0011](../decisions/ADR-0011-secretary-v1-contract.md).

## 2.1.0 — Defense logs and Secretary profile rename

Approved scope:

- raw-source re-audit and immutable ruleset v8 for the missing radius-two defense contract
- per-impact defense/Secretary audit detail with per-Nation, per-turn owner summaries
- defense and Secretary interceptions excluded from ineffective-impact totals
- repeatable rename of an existing named User-owned Secretary from profile editing
- private rename audit and immutable historical/attempt name snapshots
- no generic profile or event-aggregation framework

The detailed contract is [ADR-0012](../decisions/ADR-0012-ver-2.1.0-defense-and-secretary-rename.md).

## 2.1.1 — Defense query and migration regression hotfix

Approved scope:

- reuse the mutable, row-locked `process_cells` surface-cell index for v8 defense interception lookups
- preserve sequential missile and monster mutation visibility without changing interception behavior
- harden v6→v7→v8 migration regression coverage and clarify the stepwise release contract
- record dormant defense ownership and dispatched-mecha spawn-turn owner decisions
- keep gameplay ruleset v8 and every published v1–v8 payload/checksum unchanged

## 2.1.3 — Monster resolution and legacy queue safety

Approved scope:

- immutable v9 with only the implemented normal-monster-after-ordinary-cell-events contract
- reuse the existing ordinary shuffled cell order for a separate cell-based normal monster pass
- preserve Ghost movement limits, dispatch spawn-turn deferral, hardening, retry scope, and missile/ordinary-event random streams
- rebind existing queued ordinary, PP, SPP, and land-destruction missiles to v9 so they execute under the new ordering, without a missile-specific migration confirmation gate
- cancel only confirmed queued `queue_position > 1000` legacy residue with metadata/audit instead of guessing its old order
- document, without inventing commands, the production write-freeze and turn-cron pause/resume approval gap

The detailed contract is [ADR-0013](../decisions/ADR-0013-ver-2.1.3-resolution-and-legacy-queue.md).

## 2.2.0 — Secretary inventory/equipment foundation and in-game inquiries

Approved scope:

- Secretary secondary navigation for 熟練度, 装備, and 倉庫 without changing the existing four skills
- User-owned, Secretary-persistent item instances with a 50-instance capacity and five nullable equipment slots
- one idempotent `old_bow` starter grant for existing and future Secretaries, equipped in slot 1
- presentation metadata outside immutable gameplay rulesets
- authenticated plain-text inquiries with five categories and one optional server-MIME-validated image up to 10MB
- existing admin authorization for latest five, paginated index, and detail views
- 256-bit unguessable public attachment URLs on the existing bot-assets boundary
- no item gameplay effect, TurnEngine integration, random draw, or ruleset v10

The implementation and operations contract is [ver-2.2.0-secretary-inventory-and-inquiries.md](../../product/docs/ver-2.2.0-secretary-inventory-and-inquiries.md).

## 2.2.1 — Correctness, idempotency, privacy, and low-risk efficiency hardening

Approved scope:

- immutable ruleset v10 with only post-nutrition farm-production overflow resolution
- typed Nation-registration failures and payload-proven single-command idempotency
- typhoon facility-loss owner-log correction without gameplay or random-stream changes
- inquiry dimension/pixel limits and non-cacheable static attachment responses
- PostgreSQL identity-level OAuth concurrency serialization
- command-definition and `/me` query-count reductions with response-equivalence coverage
- application-version single source, complete-app PHPStan, non-cancelling PHPUnit shards, and one validated Composer dependency artifact

The implementation, exclusions, and operator checklist are
[ver-2.2.1-correctness-hardening.md](../../product/docs/ver-2.2.1-correctness-hardening.md).

## 2.5.0 — Secretary public profile foundation

Approved scope:

- public Secretary「メイン」profile as the leftmost tab, with responsive portrait, basic information, biography, and five read-only equipment slots
- one replace-only 3:4 main image per Secretary, using the existing safe web-image upload boundary on a separate public storage route
- required creation-method metadata and optional short author/rights credit, with public image information disclosure
- per-User AI-generated-image visibility and missing-image fallback preferences; unset preferences remain visibly unset
- Secretary level derived only from the canonical four passive-skill levels
- immutable ruleset v14 applying that level as the uncapped percentage multiplier for money and food capacity through `NationCapacityResolver`
- exact forward-only v13-to-v14 migration preserving production state and provenance
- no gallery, history, multiple portraits, generic profile/media/modifier framework, social interaction, or new Secretary XP system

The decision and implementation contracts are [ADR-0016](../decisions/ADR-0016-ver-2.5.0-secretary-profile.md) and [ver-2.5.0-secretary-profile.md](../../product/docs/ver-2.5.0-secretary-profile.md).

## 2.6.0 — Oil as a Nation resource

Approved first-PR scope:

- immutable ruleset v16, leaving the published v15 payload and authored bytes unchanged
- normal tradable `oil` Nation resource, displayed as 石油 in 万バレル, initially zero and capped at 5,000 internal units
- fixed sale rate of one oil unit to two internal money units through the existing sale-policy engine
- seabed oil field output changed from direct money to 500 oil units per Turn
- exact forward-only v15-to-v16 production upgrade adding zero oil balance and the ordinary default sale policy while preserving every existing balance and policy
- definition-driven API and existing resource-list UI presentation
- no trading post, player trade, port, ship, fuel consumption, oil command, market-price change, oil-specific policy, or new generic resource framework

## Later 2.x candidates

Item gameplay effects, accessory effects, PD, active skills, blueprints, Secretary image galleries and multiple portraits, conversation, gifts, item leveling, auctions, trading, and multiple-bow builds remain candidates only. They require explicit owner approval, their own decision gates where applicable, and new immutable rulesets when gameplay changes. The 2.2.0 inventory/equipment state and 2.5.0 capacity delta are not an effect engine or generic modifier framework.

## Beyond 2.x

ver 3.x or later may revisit historical derivative works and 箱庭 culture after usage conditions are reviewed. No behavior is approved by that direction alone.
