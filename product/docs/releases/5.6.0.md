# 5.6.0 露店の無期限化・船と首都の命名

地底交流場の露店を無期限にし、自国の船と首都に任意の名前をつけられるようにする。露店・合成・チケットの画面改善、一括狩場スキップの歪んだ輝石合計の表示修正、既存処理の共通化、現行仕様と運用文書の照合を含む。

application **5.6.0 / Ruleset v41**。基準mainは `7b312096e7ea7d9aa8be40baf932143621f9befb`。releaseからmainへの統合PRは[#315](https://github.com/Mamiki765/hakoniwa-world/pull/315)で、最終HEAD・CI・マージ結果は同PRに記録する。本書はコードのリリース範囲を示し、本番への適用完了を意味しない。

2026-10-19のOwner指示で、開発中の`release/5.5.1`を`release/5.6.0`へ改名した。旧[#306](https://github.com/Mamiki765/hakoniwa-world/pull/306)はCLOSEDで、改名前の履歴参照に限る。改名自体ではRuleset・migrationを変更せず、船と首都の命名は後続の#319で統合した。

## 変更する挙動

- 新規・既存のactive出品は時刻で失効せず、購入か出品者の取消まで保管庫枠と出品枠を使う。島放棄時の取消は維持する。
- 同時active 5件、NPC売値以上、手数料10%・受取floor(price×9/10)、手持ちG払い、装備可能な所持品による購入IL上限、保管庫容量、二重購入防止、代金受取と再送の契約は維持する。
- 一覧・購入・取消・赤丸集計から期限判定を除去する。元の失効処理はリクエスト時に実行する方式であり、別の定期失効ジョブはない。
- 画面の残り日数・残り時間と販売期間の説明を削除する。過去の期限切れ履歴と表示したIDだけのseen更新は残す。
- 自国の船・首都に1〜16 Unicodeコードポイントの任意の名前をつけ、空入力で解除できる。地図の選択マスから操作し、ターン・計画枠・進路・戦闘には影響しない。名前は公開地図と既存の公開対象イベントにも表示し、過去ログは書き換えない。入力・権限・表示・保存の詳細は[船と首都の名前](5.6.0-given-names.md)を参照する。
- 露店・合成・チケットの表示を改善し、戦闘ログ・問い合わせ画面の責務を整理する。一括狩場スキップでは残高へ加算済みの歪んだ輝石を新しい結果snapshotの`distorted_stones`へ合計保存して表示する。報酬加算・乱数消費・lock・順序を変えず、再送は保存済み合計を返す。過去のsnapshotへ合計を後付けしない。

## 版と移行

application versionは5.6.0、現行Rulesetは `hakoniwa-2s-plus-v41`。v40は変更しない。v41のBehaviorに `listing_expiration = none` を置き、以前の `duration_hours` を現行payloadから除く。出品数・比率等のDataは維持する。

release全体で正規のforward migrationを3本追加する。

1. `2026_10_18_020000_make_underground_market_listings_indefinite.php`: expires_atをnullableにし、active行だけをNULLへ移す。PostgreSQLのmigration transaction内でDDLのtable lockを保持し、状態更新と競合させない。sold/cancelled/expired行、品物の所有・出品フラグ、残高、未受取代金、結果receiptは変更しない。
2. `2026_10_18_030000_publish_indefinite_market_ruleset.php`: World lockと未解決公式Turnのguardを維持し、v40のWorldをv41へ進める。既存queueのrequest identityと怪獣の出現時provenanceは維持する。
3. `2026_10_19_000000_add_ship_and_capital_given_names.php`: `ships.custom_name`と`nations.capital_name`をnullableの`varchar(16)`で追加する。既存行は未設定のNULL。表示専用の名前追加によるRuleset世代の追加はない。

露店無期限化には新しい完全な構造fingerprintを追加し、命名の追加列は型・NULL可・既定値なし・照合順序を個別に検証する。旧baseline・5.5.0の構造manifest・過去migrationを上書きせず、これらのmigrationにdownは提供しない。

## APIと既存履歴

現在のactive一覧と新規出品の `expires_at` はNULL。終端履歴には旧期限日時が残ってよい。既存結果receiptのsnapshotは変更せず、v40の出品リクエスト再送は当時の期限日時を含む結果をそのまま返す。その日時は現在の有効性判定には使わず、画面にも期間として描画しない。

既に期限切れた出品を再びactiveにしたり、売却済み・取消済みの品物を戻したりしない。未受取代金・旧期限切れの赤丸/既読は従来どおり処理する。

## 作業と本番適用の境界

Ownerはリリース説明の更新と、検証成功後の#315のmain統合を承認済み。本番deploy・本番migration・未解決Turnの自動retryは含まない。リポジトリのワークフローはQualityとForgejoへのGit同期で、本番デプロイ処理はない。mainへのpushではQualityが自動起動しないため、マージ後のmainを対象に検証用のQualityを実行する。

マニュアルの追加掲載範囲、未採用のC2復旧案、別件のresonance-bounds修正を本リリース締め作業へ追加しない。本番適用時は[移行と運用の入口](../operations/current-deployment.md)から、対象SHA・image・migration・World Ruleset・未解決Turnを改めて照合する。
