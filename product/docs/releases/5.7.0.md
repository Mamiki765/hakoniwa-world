# 5.7.0 怪獣図鑑・地上アイテム図鑑

秘書メニューに図鑑を追加し、出会った怪獣と手に入れた地上アイテムの情報を読めるようにする。登録に応じたPdのプレゼントと、既存記録から過去の登録を補う運用コマンドを含む。

application **5.7.0 / Ruleset v41**。`release/5.7.0` から `main` へ統合する。基準mainは `a3c293dee3299bd0d6a71177422403a397495b94`、機能統合HEADは `2ccd82f2e7ad6a4b96c359b6afa6fdfef674303e`。最終HEADのCodex reviewとCIはリリースPRに記録する。本書はコードのリリース範囲を示し、本番への適用完了を意味しない。

## プレイヤー向けの変更

- 図鑑はプレイヤー単位で保持し、島を作り直しても登録と受け取り済みの記録が残る。
- 自分の島の攻撃で怪獣のHPを実際に減らすと怪獣を登録する。地上アイテムは秘書の倉庫へ入った時に登録する。
- 未登録の名前は「？？？」として隠す。登録済みなら、怪獣の特性やアイテムの最大Lv・効果・売値などを読める。
- 1項目につき5Pd、合計10項目の登録ごとに20Pdを1回ずつ受け取れる。まとめて受け取りと未受取の赤丸表示を用意する。

登録条件・公開情報・API・過去記録の採用範囲は[図鑑の仕様](5.7.0-collection.md)を参照する。

## 本番適用時の手順（今回未実施）

対象SHA・image・backup・migration・World Ruleset・未解決Turnは、[運用の入口](../operations/current-deployment.md)から適用時に確認する。本番deploy、migration、backfillは別途Owner承認が必要で、このリリースPR作成・レビュー作業では実行しない。

1. 承認された対象をデプロイし、`php artisan migrate --force` で図鑑用の表を追加する。migrationが完了してから図鑑を利用する。
2. `php artisan hakoniwa:backfill-collections --dry-run` で候補数・ユーザー数・種別と記録元ごとの件数を確認する。オプション省略もdry-runで、候補数は既存登録を除いた新規挿入予定数ではない。
3. Ownerが件数を確認し、適用を承認した後に `php artisan hakoniwa:backfill-collections --apply` を実行する。挿入数は `inserted` で報告される。
4. 既存の登録・受取状態を保持し、記録が古い場合は初回ターン・登録日時を補正する。繰り返しても登録や報酬は重複しない。backfill自体はPdを支払わず、未受取の項目はプレイヤーが受け取る。

残っていない記録は復元せず、次回の取得・攻撃で登録する。未解決Turnの自動retryは行わない。
