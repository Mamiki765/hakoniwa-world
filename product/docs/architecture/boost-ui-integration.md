## 最新#332との契約照合

固定HEAD `de775082e63d2c8d79c8071f9ca1a6376c310102` の `App.vue` は、開催中を「停止補填中：追加ターンあり（未補填分のみ）」と表示する。旧「60分ごと」や「奇数時にも追加」の表現は実コードに存在せず、可変間隔でもTOPのこの残件は解消済み。次回時刻は既存の `worldSummary.next_scheduled_turn_at` を使い、`turn_interval_minutes` から計算しない。`AppBoosts.shared.test.ts` の期待値も汎用表現に追随している。下記の固定コードとの隔離統合でも確認した。

`boosts.ts` の `turn_interval_minutes` 型コメントはまだ「奇数時を追加できる期間の名目的な間隔（60）」となっている。最新契約は予約した候補間隔（例30分）で、通常枠を除いた後の実行間隔や成功を保証しない。コメントを更新し、`effects` には `additional_turn_interval_minutes`, `additional_turn_limit`, `additional_turn_scheduled_ats` の明示型を加えるのが残る追随点。`compensation_only` は既に型定義・表示分岐へ追加済み。旧 `additional_turn_hours_jst` はサーバーから返さない。#332のindex signatureは新しいeffects値を許容するが、型コメントの訂正を実行時の検証完了とは扱わない。

`BoostBanner.vue` はAPIの `description` を優先し、追加枠の間隔・上限・未補填条件をサーバーの予定から表示できる。狩場descriptionはG・鍵の個数が増えないことを明示する。公開APIは各種別の開催中または次回を1件返し、`meta.server_now` で端末時計差を補正する。#332は5分ごとに再取得するため、管理室取消から表示への反映は最大約5分遅れることがある。表示の遅れは効果の適用可否に使わず、サーバー受付時の判定を正本にする。タイトルとdescriptionはplain textで表示する。

公開帯の型・コメントの追随はラピスの#332側、追加予約・管理室・サーバー契約は#334側とする。#334から相手branchを書き換えない。公開帯を含む機能には両PRが必要で、両方ともmain向けの別PRのまま検証し、マージしない。
