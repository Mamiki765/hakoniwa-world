# 4.13.0 海域天候

16×16チャンクを海域として、公式Turnのセル処理開始時に各海域を独立抽選する。
保存値は処理された当ターンの天候であり、予報ではない。

| 天候 | 抽選枠 | 効果 |
|---|---:|---|
| 晴れ | 通常重み45 | 表示用 |
| 曇り | 通常重み25 | 表示用 |
| 雨 | 通常重み20 | そのTurnの森林自然成長量を2倍 |
| 雪 | 通常重み5 | 表示用 |
| 雷 | 通常重み3 | 表示用 |
| 台風 | 絶対確率1.4% | 当選海域内の既存対象施設へ台風判定 |
| 流星群 | 絶対確率0.55% | 当選海域内の実セルから一様・重複可で着弾 |
| 終末 | `A × 海域内実セル数 / S` | 海域内を一様に選んだ中心へ巨大隕石 |

Ruleset v31に災害の絶対確率枠と通常天候の相対重みを分けて持つ。
先に台風・流星群・終末を一つの排他的抽選で選び、当たらなかった場合だけ通常天候を
45:25:20:5:3（合計98）で抽選する。災害率合計をDとすると各通常天候の無条件確率は
`(1−D) × 重み/98`。通常天候の追加・重み調整・将来の季節補正で災害の周辺確率を変えない。
JSONBのobject順序に依存せず、海域座標とversion付き専用streamで再試行を再現する。

雨は既存の秘書補正後の自然成長量を2倍にし、森林上限と所有/処理条件を維持する。
中立森林は既存どおり自然成長の処理対象外。
植林の追加本数・伐採収入は変えない。天候はセル処理前に確定するため、同じTurnに効く。

台風/流星群/巨大隕石を旧World災害の機会抽選から除外する。台風/流星群にはWorld面積補正・
中心padding・radius抽選を使わない。地震→津波→台風/流星群→巨大隕石→噴火の既存相対順序を維持する。
台風の破壊・風力故障・防風・保護・お守り、流星群の確定1発と50%継続（平均2発）、
着弾・船舶・施設・首都・宝物等は既存効果経路を再利用する。隣接海域の防風源は参照する。

## 終末と世界外帯

World実矩形の幅をW、高さをH、MapBoundsの16×16 canonical海域数をCとする。
旧巨大隕石の期待回数は `A = C × 16/225 × 0.05 = 4C/1125`。
旧中心抽選の2マス余白を含む面積は `S = (W+4)(H+4)`、世界外帯は `B = S−WH`。
既存の巨大隕石probabilityはこの期待値入力として使い、旧global trigger/center/opportunityは実行しない。

- 各海域の終末確率は `A × 実海域面積/S`。台風・流星群とともに排他的な絶対確率枠として選び、
  残余だけを通常天候の重みへ配分する。部分海域の中心も実矩形内を一様に選ぶ。
- 外帯の期待回数は `A × B/S`。整数部を確定回数、端数をBernoulli抽選とし、1回に丸めない。
  外帯中心は角を含む四つの重複しない帯のindexへ直接変換し、座標一覧を生成しない。
- 幅・高さ・C・S・Bはターン内で一度計算する。確率は整数の分数で扱い、基点精度への丸めを避ける。
- 各座標の巨大隕石着弾期待値 `A/S`を維持する。同時発生数の分布や重複被害分布は旧方式と異なる。
- 半径2の既存被害処理、World端のclip、宝物・船・首都・施設の処理を再利用する。爆風は海域境界を越える。
  記念碑飛ばしの経路・被害処理は変更しない。巨大隕石のプレイヤー向け発生ログは従来の中心座標文面を維持する。

W=80、H=64、C=20では通常海域の終末確率は約0.31870526%、外帯は約0.73700591%。
負座標・部分海域のCは単純な `ceil(W/16)ceil(H/16)`ではなく座標範囲の海域数で数える。
旧機会数、現行5%、中心padding=2、MapBoundsの計数は承認式と一致した。

## 保存・移行

- MapChunkにnullableな`weather_key` / `weather_turn`のみ追加。導入前/新規海域は記録を生成せず晴れとして扱い、次の正式Turnで抽選する。
- 天候は全対象海域を一括取得・一括保存する。既存World transactionでrollbackし、同run/seedのretryで再現する。
- 実World範囲へclipし、実セルを持つ海域だけを扱う。天候のためにMapCell/MapChunkを生成しない。
- 当選災害のセル、防風halo、海域内/外帯の巨大隕石blastは一括取得し、船舶indexも共有する。
- forward-only migrationはv30 payloadを保持してv31へ移す。未解決production Turnがあれば更新を拒否し、履歴のseed・Ruleset・要求provenanceを変えない。
- 台風/流星群の初回公開ログは既存文体の「台風の被害が出ています。」「流星群が降り注ぎました。」を維持し、既存resolverの海域名と実座標inclusive範囲を表示する。巨大隕石/外帯は海域名なしの従来落下文面、天候ラベルだけ終末。
  乱数・seedと秘密情報の公開境界は維持する。

## 今回の範囲と確認

`sea_areas`はMapChunkをまとめて取得し、海域座標・実範囲・名前・最後に処理した天候/Turn・
画像descriptorだけを投影する。導入前/新規海域は晴れを投影し、未記録Turnはnullとして画面に架空のTurnを出さない。秘密セルや乱数情報は含めない。

main `73058649357a979ada70b0cdbcbfb699ac2cb9ad`と同じ隔離PostgreSQL・development image・
World fixtureで各1回測定した。単発のwall timeは観測値であり速度保証ではない。

| fixture / phase | 旧SQL数 → 新SQL数 | 旧SELECT → 新SELECT | 旧時間 → 新時間 |
|---|---:|---:|---:|
| 60×60 mature / process_cells | 3,141 → 3,143 | 17 → 18 | 16.160s → 16.327s |
| 32×32 forced typhoon / global_disasters | 343 → 271 | 12 → 13 | 1.615s → 1.299s |

通常セル処理は16海域分でも抽選取得・保存の2 SQLだけ増える。台風fixtureのdamageは
旧165 cells/旧半径から新128 cells/1海域へ変わるため、速度差を同等仕事量の改善とは扱わない。

新側は終末追加後、通常天候重みの最終変更前に測定した。流星群/終末の旧/新時間比較は未測定。
