# 5.8.0 予約ブーストと永続ターン実行枠

Owner の「次のminor」指示により、main の application 5.7.0 に続く5.8.0として実装する。基準は `ae98c3d81823bf948987016f42253a2d7a786396`。作業branchからmain向けDraft PRを作り、本番操作・実イベント予約・マージはしない。PHP・Dockerfile・Composer依存の更新を含めない。

時間加速は停止補填用途の単発予約。通常JST偶数時00分を保ち、開催期間内の奇数時00分に追加する。未補填枠と実行時刻をターン番号から切り離して永続化し、常駐worker、cron、管理室の手動更新をWorld lockで直列化する。現在枠は一度だけ実行し、未解決失敗を自動retryしない。停止中に過ぎた枠の無制限catch-upは行わない。

狩場ブーストは再利用可能なお祭り用途。レア出現率2倍・通常敵の鍵出現率2倍・XP2倍、確率100%上限、レア確定鍵の数量・G・他報酬は維持する。単独/PT/単独skip/一括skipへ受付時snapshotを渡す。試練・宝物庫・異世界・イベントには波及させない。

イベントの種別と固定倍率は今回Ownerが確定した操作の意味で、任意倍率の別catalogを導入しない。開催日時と有限繰り返しは運用データ。既存Ruleset v41と既存snapshotを変更せず、Ruleset世代は増やさない。予約・実行枠・通常枠カーソルを追加するforward migrationは隔離DBでのみ検証する。

公開・管理API、開催回の識別・取消、JST/UTC、プレビューの形式と制限は[API契約](../architecture/boost-scheduling-api.md)、常駐起動と移行上の境界は[運用手順](../operations/turn-scheduler-worker.md)を参照。

## UIとの統合

画面側は別Draft [#332](https://github.com/Mamiki765/hakoniwa-world/pull/332)、確認HEAD `43e86210b383776124551b0750bc79d9c3c50e26`。サーバー側は公開APIの配列envelope、`turn_acceleration`、`turn_interval_minutes:60`、`multiplier:2`、plain text description を仮契約へ合わせる。TOP・島・地底の帯を重複実装しない。

公開APIは種別ごとに開催中または次の開催回を1件返し、管理APIで全予約（最新500回）を確認する。管理室フォームは本PRで既存ターン操作欄へ接続し、JST日時・毎日/毎週・プレビュー・確認予約・開催回/以後系列の取消を扱う。「遅延ターン分」ボタンから時間加速を入力できる。API未実装時は#332が非表示になるため、どちらを先に統合しても基本画面を継続できる。両PRはmain向けの別PRのままとし、どちらも本タスクではマージしない。

UI側に必要な契約調整: TOPの「60分ごと」だけでは未補填解消後に追加枠が省略されることが伝わらないため、「通常偶数時＋期間内奇数時、未補填分のみ」の表現へ更新する。狩場はAPI descriptionを使い、G・鍵の個数まで2倍と読める包括表現を避ける。具体的な差分の所属と危険な誤表示の残件は[画面連携の引継ぎ](../architecture/boost-ui-integration.md)に記録する。
