## 4. 本体実装前に詰める未決点（既決事項を再質問しない）

### A. ratingの基準IL

武器・防具ILを使う方針はOwner指定。`max(200,min(武器IL,防具IL))` は前Chatの提案であり、Owner確定とは扱わない。

min案は武器だけ更新した時の補正低下を避ける一方、鎧を更新した時に物理威力/会心等も下がり得る。**この点についてOwnerは、鎧を更新せず高いエンチャ効果を求め、代わりに低いHPで戦う構成を許容した。** 古い鎧を選べること自体を不具合・塞ぐべき抜け道・実装停止理由としない。

これはトレードオフの許容であって、min式・分母・丸め等の最終承認を代用するものではない。min案を有力な比較案として扱い、mean/maxも残したprobeは設計検討用のままとする。

さらに「基準より高ILのアクセは実効%も増やす」か「IL先行だけによる上積みは100%効率まで」かも未決。実装者が独自の効率上限を足さない。

### B. 倍率・ratingの適用範囲

Owner補足: HPや攻撃が同じ装備世代の倍率で伸びるなら、回復だけを旧世代の数値に置き去りにしない。エンドコンテンツでは同世代同士の戦闘バランスと、数字・装備世代の成長を両立させたい。

**以下はChatの整理案であり、Owner確定の細則ではない。**

| 効果 | 一度だけ倍率を反映する案 |
|---|---|
| 固定量・能力値依存の回復 | 術者側の武器IL倍率を回復出力へ反映する案。対象の鎧ILで無条件に回復力を増やす案とは区別する。 |
| 最大HPの一定割合を回復 | 倍率反映済みの最大HPから回復量を求めるなら、同じ成長をさらに後掛けしない。 |
| 実与ダメージの一定割合を吸収 | 攻撃出力が既に倍率反映済みなら、その実ダメージから算出する。回復倍率を重ねて二重成長させない。 |
| 障壁 | 固定量/能力値依存か、最大HP依存かを区別し、同じ一度反映の考え方を候補にする。障壁の最終仕様は未決。 |

例示のみ: 同じ倍率1.21をHPと回復へ一度ずつ反映すると、HP10,000→12,100、回復1,000→1,210となり、他条件が同じなら1回で戻るHP割合は10%のまま。武器と鎧のIL差、エンチャや技の選択による差まで均一化する目的ではない。

なお武器倍率の通常攻撃/技/反撃/継続ダメージ/固有追撃への適用範囲、防具倍率をかけるHPの範囲、HP変化時の現在HP・覚醒・再生の扱い、武器・鎧のOPも含むrating化と固定特殊効果の区別は引き続き詰める。

これは全経路へ新テストを作る指示ではない。同じ意味が通る共通処理を先に定めるための読込範囲。

### C. 旧品の意味と表示

- 旧IL210武器にS=1.1を適用するなら、旧品装備者の戦闘結果は変わり得る。「NPC本体を変えない」と「戦闘難易度が完全に同じ」は別。
- 黒竜晶210→200はILを置換して現在のgeneratorで再抽選するだけでは不十分。型・基礎値・OP品質・研磨を保つことが目的。
- 旧weapon powerは低Lvでは小さな寄与とは限らない。隠すだけで数値を消したり武力/精神へ移し替えたりしない。旧品の比較をしやすくする詳細項目は別途考える。200超の内部加算値を今後さらに伸ばすかは後回しでよく、220までの準備に新しい個別カーブを先行追加しない。
- 通常OPのIL101〜200横ばいは、移行時に勝手に強化/弱体化して埋めない。
- 物理+ratingの括弧内はまず実効の追加補正。既存の同系補正に加算される場合、「総DPSを必ずその%増やす」とは表示しない。装備比較は装着後の武器/鎧を含めて再評価する。

### D. 経済・転生のscope

鉱石加工・素材市場は今回の検討から外す。装備売買は本来の目的に沿って検討を継続するが、4.6へ含めるとはまだ決めない。転生、技/アクセ枠拡張、共有レイド、工房等を一括実装しない。まず装備成長と狩場4を主軸にする案を維持する。

## 5. 今回動く比較スクリプト

```sh
# DB・Laravelなし。標準出力だけへ結果を出す。
php product/docs/plans/4.6.0-preparation/rating-probe.php
php product/docs/plans/4.6.0-preparation/rating-probe.php \
  --weapon-il=220 --armor-il=220 --item-il=220 --rating=840 --source=new --json
```

- Ownerの倍率案だけを計算し、min/mean/maxの未決案を並べる。
- 仮のrating換算単位は100=1 percentage point。Ownerの表示例の換算率を確定するものではない。
- 旧品では保存された基準ratingをそのまま使う。newは同じrollに装備IL倍率をかける案を比較する。
- 旧rating 840・武器220・鎧200なら、min案の実効補正は8.4%。鎧だけ210へ上げると約7.6364%。このような装備交換のトレードオフを本体実装前に見られる。低IL鎧を選択すること自体はOwner許容。
- S(200)=1、S(210)=1.1、S(220)=1.21。新規220の同じ基準rollは1016.4rating、基準220では再び8.4%となる（丸め前の設計値）。
- floatを用いるのは一時比較のみ。本番の数値型、丸め、cap、戦闘式を採用したことにはならない。DPS・HP・勝率は測っていない。

## 6. 提案する実装順

1. **Chat側の次作業:** A〜Cを小さな仕様表に収める。原本保存/投影の境界、倍率対象、比較UIまでを決める。場当たり的な個別曲線を追加しない。
2. **Codexへ最初に渡す範囲:** 装備倍率・rating表示/解決・黒竜晶正規化の一塊。既存シミュレーターとsupported upgradeで接続を検証し、未release設定の同じ変更境界へまとめる。
3. **並行するChat作業:** 帰港地の敵役割・景観・ドロップ/XP候補を作る。案内人台詞と試練4本文は創作しない。ここでは未決の敵HP/攻撃を確定させない。
4. **Codexの次作業:** 固まった装備式を前提に帰港地を組込み、代表構成で敵とXP/報酬を調整。旧IL550等の線形外挿レポートを新式の目標ILとして流用しない。
5. **別判断:** 装備売買、転生、試練4をどこまで同releaseへ入れるか。鉱石案は進めない。UI小修正や貸出コメントはこの大枠と区別する。

同じ大きなVueやcombat本体をChat/Codexが同時に触らない。Chatがパッチを作る場合は基準SHAと担当ファイルを固定し、Codex側の仕上げ時に取り込む。

## 7. テストを増殖させない境界

恒久テストの追加はAGENTSの基準どおり、到達経路・故障・既存の代表で検出できない理由を示せるものだけ。最初から「全IL×全武器×全職×全seed」を要求しない。

倍率表や仮rating比較はこのような一時probe/reportへ置く。ゲーム数値をそのまま期待値として複製しない。実装時は既存の所有装備解決、貸出同期、装備戦闘、必要なupgradeの代表へ最小限の追補/置換を検討する。機能追加ごとの永久matrixや、大量の境界値ガードを先行しない。

初回準備ではproduction code変更0、schema変更0、恒久test追加0。standalone PHPの構文と代表計算だけが確認対象。今回のOwner補足反映は本文のみで、probeも変更しない。repository-wide PHPUnit、PHPStan、ブラウザ、CI、production検証を成功項目に含めない。
