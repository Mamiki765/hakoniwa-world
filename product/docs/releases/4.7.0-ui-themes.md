## 表示不良

- 地上から選ぶ地下施設詳細は、未定義 `--surface` の白 fallback と Dark の明るい継承文字色が組み合わさっていた。背景を既存 `--selected-surface`、本文を `--ink`、選択枠を `--coral` に揃えた。テーマ別 DOM 分岐は追加していない。
- 狭い画面の `.hud-more { color: white; }` が旧テーマの白い資源推計・詳細欄へ継承されていた。旧テーマでは `.hud-more` も本文色に揃えた。
- 利用ルールの連絡先リンクボタンは濃い背景を持つため、旧テーマの通常リンク色で上書きしない。通常・訪問済み状態の文字は `--on-solid`、hover の明るい背景上では `--ink` を使う。

## 資源・売却方針

独立した資源売却ページとヘッダーナビを除き、自島 HUD の下へ折りたたみで配置した。閉じた状態の下に重複した一覧は置かない。デイリークエストの小さなボタンを同じ行に置き、未達成項目があると既存の赤丸を表示する。開発画面を開いた後に既存進捗 API で取得し、コマンド・地底の達成通知にも連動する。

各バーは現在の個別容量を右端に使う。食料容量は現在の API と同じ実トン数で、栄養値による換算を入れない。石油は既存の万バレル単位を使う。バーの0〜1000は位置の分解能だけで、ゲーム上限や保存量にはしない。

- 小麦以外: 左端0 → `sell_all` / null、右端容量 → `stockpile` / null、中間 → `keep_amount` / 保持量。
- 小麦: 左端は人口と同じトン数 → `keep_amount`。数値入力も人口未満を拒否する。人口が容量を超えた場合は右端 `stockpile` に固定し、バーと数値欄を無効にする。
- 数値欄ではバーより細かい量や容量を超える保持量も正確に設定できる。既存 backend は容量超過の保持量を禁止していないため、新しい保存上限を作らない。
- 既存の小麦設定が新しい UI の安全範囲より低い場合、編集欄を調整して通知する。保存操作までは書き換えない。既存 API が保持量0を受け取る契約も維持する。
- 保存は資源ごとに明示操作。既存 PUT の `policy`、`keep_amount`、`expected_version` を送信し、409では再取得して最新 version を使う。

3カラム、横スクロール、`workspace-jump` のジャンプ操作、地図・コマンド・開発計画、デイリー報酬、scene asset、AI画像設定、4.6.2 の application version refresh は維持する。

## 検証

テーマ選択・cookie保存・復元、3カラムとジャンプ、資源3方針の送信、容量を使うバー、正確な数値、409再取得、小麦の安全範囲、デイリー赤丸を既存の代表テストで確認する。CSS snapshot や authored 値・種類数を固定するだけのテストは追加しない。

Frontend は `npm run test:all`、`npm run typecheck`、`npm run build`、`npm run lint`。Backend は最終 HEAD の Quality CI（全 shard、`FirstProductionReleaseTest`、`CommandQueueAndSalePolicyTest`、`TurnEconomyTest`、`SurfaceParadoxDailyRewardTest` 等）で確認する。ローカルは PHP と Docker daemon が使用できないため backend 実行不可。

PC・狭い画面・スマホの表示は、実際の Vue/CSS を fixture API と組み合わせたローカルプレビューで確認する。5テーマの自島・資源欄・詳細・デイリーモーダル、地下施設選択、秘書各タブ、交易場、地底各メニュー、マニュアルの表と利用ルールの連絡先、スマホの横スクロールジャンプ、小麦の固定を対象とする。文字と背景の実際の継承を調査した一時的な結果と screenshot は repository 外に保存し、永続的な CSS snapshot test は作らない。マニュアルのプレビューは実 CSS と本文・Bladeと同じ構造を使った簡易レンダリングで、Laravel のレンダリング自体は CI に委ねる。保存確認はメモリ内 fixture のみで、本番接続・DB変更・deploy は行わない。実データ・本番 asset を揃えた表示はこのプレビューでは保証しない。
