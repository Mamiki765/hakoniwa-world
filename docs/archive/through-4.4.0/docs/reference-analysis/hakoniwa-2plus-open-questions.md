# 箱庭諸島2＋ 未解決事項

## 状態区分

- **不具合候補**：コードとコメント、API慣例、または同一コード内の前提が食い違う。隔離実行または追加判断が必要。
- **旧仕様の曖昧さ**：実装結果は読めるが、それが意図されたゲーム仕様か確定できない。
- **新作の設計質問**：旧実装には答えがなく、実装前に決める必要がある。

## 不具合候補

### 1. 排他制御の成否判定

`Util::lock` は `flock(lockFd, LOCK_EX)` が非0なら成功、0なら失敗として終了する（`util.c:123-133`）。通常のPOSIX仕様と逆である。`open(Value::dirName, O_RDWR)` の失敗も検査しない。

確認事項：原配布環境固有の戻り値前提があったのか、単純な逆判定か。次段階の隔離環境で実行traceを取る。

### 2. `logMax` が設定から読まれない

宣言、既定値、`config.cgi` には `logMax` があるが、`Value::input` のkey分岐にない（`value.h:109-110`; `value.c:30,79-164`; `config.cgi:67-68`）。実際には常にコード既定8と考えられる。

### 3. 海底基地の建設条件

コメントは海限定だが、条件が `land->kind != Land::Sea && land->kind != Land::SeaDeep`。`SeaDeep` はparam定数0で、`Sea` kindも0である（`command.c:509-521`; `map.h:139,154`）。結果として深海限定ではなく全海paramで建設可能に見える。

確認事項：深海だけ、油田を除く海、全海のどれが本来仕様か。

### 4. 村発生率の未使用変数

海際度から `ratio=5/10/20` を計算するが、判定は `dice(100) < 20` 固定（`map.c:321-341`）。海際度を発生率へ使う意図が残骸化した可能性がある。

### 5. Y座標の補正先

コマンド座標で `y >= worldSize` のとき `x = worldSize - 1` とする（`command.c:136-142`）。`y` の誤記に見える。ただし、その前に未補正座標で `Map::getLand` を呼び、範囲外ならreturnするため通常経路で補正自体が機能しない（`command.c:127-142`）。

### 6. 食料コストの不足判定

負のcostを食料コストとするが、不足検査が `island->food < cost` なので非負食料なら成立しない（`command.c:163-178`）。後続処理は `MIN(food, -cost*amount)` で残量まで送るため、実挙動は「不足で失敗」ではなく「残量分だけ輸出/援助」となる（`command.c:566-603`）。ログ101が事実上出ない可能性がある。

### 7. 新規登録の範囲外中心

座標の範囲検証がなく、範囲外を中立として数える（`new_island.c:50-59`; `Map::countNeutral`, `map.c:126-140`）。端で不完全な初期国、または生成用 `while` の停止不能が起こり得る。

### 8. 初期マップの一時フィールド

`Land::initialize` は `kind`, `param`, `owner` だけを初期化し、`flag`, `seaLevel` を初期化しない（`map.c:1226-1231`; `map.h:171-179`）。ファイルへ書いて次リクエストで読めば0になるが、同一プロセスで初期化直後に利用する経路の安全性は要確認。

## 旧仕様の曖昧さ・堅牢性不足

### ターン遅延

1アクセスで `lastTime` を1区間だけ進める（`main.c:35-40,72-76`）。長時間アクセスがなかった後、後続アクセスごとに1turnずつ追いつく挙動が意図か、単なる簡略化か。

### 国境感化

施設能力に関係なく、ランダム隣接ownerへセルが即時変更される（`Map::infLand`, `map.c:211-260`）。どのゲーム説明上の意味を持つか、現代化時に「人口圧力」「侵食」「占領」のどれとして扱うか。

### 国家消滅時の地形

全所有セルを即時に海へ変える（`Map::deleteIslands`, `map.c:1168-1183`）。地殻変動という仕様か、領域掃除の実装都合か。

### バックアップ整合性

複数 `.cgi` を個別に行コピーし、空行を捨てる。復旧は現役削除後にrenameする（`mentenance.c:89-151`）。書込途中のsnapshot、コピー失敗、rename失敗を検出しない。どこまで実運用で復旧可能だったかは静的解析だけでは不明。

### データ破損時

map/info/commandの長さ、数値、参照、16進文字を検証しない（`hako_io.c:38-152`; `info.c:75-214`; `map.c:39-47,1240-1255`; `command.c:62-71,110-117`）。破損を黙って0等へ変換する場合と、null参照へ進む場合が混在する。正式な復旧規約はない。

### 設定値の値域

負数や0を拒否しない。`backUpTurn=0` は剰余、`worldSize<=0` は配列確保/乱数、`commandMax` は配列、災害率>1000は常時発生等に影響する（`Value::input`, `value.c:79-164`; `turn.c:145-148`; `Map::alloc`, `map.c:13-16`; `Util::dice`, `util.c:62-65`）。

### アーカイブとマニュアルの版表示

対象アーカイブ名は `hakow094.tar` だが、マニュアルは必要ファイルを `hakow090.tgz` と記す（`hakow-readme.txt:45-58`）。094固有の変更履歴は同梱資料にないため、どの仕様が090から変わったか不明。
