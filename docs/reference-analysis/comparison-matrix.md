# 箱庭諸島2＋とやまにてぃの比較表

## 目的と判定基準

本表は、箱庭諸島2＋の共有世界ルールと、やまにてぃの現代的な実装技法を分離して比較し、新作で独立実装する方針を示す。確定していない項目は「暫定」または「要決定」と明記した。

根拠は Phase 1 の各 hakoniwa-2plus 文書と、Phase 2 の各 yamanity 文書である。第三者コードの直接移植を意味しない。

| 観点 | 箱庭諸島2＋ | やまにてぃ | 新作で採用する方針 | 採用しない理由・注意点 |
|---|---|---|---|---|
| 言語・基盤 | C製CGI、ファイル保存 | Laravel 10、PHP 8.2、Vue 3、MySQL 8 | Laravelによる独立実装。Vueは候補として採否を別決定 | Cの逐語翻訳、Laravel雛形のコピーはしない |
| 世界モデル | 60×60の単一共有世界 | 島ごとに独立した15×15マップ | 地上は初期60×60の共有世界 | 島単位マップは国境・占領・共有災害を表現しにくい |
| マップ保存 | 世界全体を固定長テキストで保存 | 島・ターンごとに225セルをJSON保存 | セルの検索可能項目は正規化し、チャンク単位で取得・更新 | 巨大な単一JSON、毎ターン全スナップショットは避ける |
| セル表現 | 地形1桁、値2桁、所有者2桁の5桁16進 | kind、value等をJSONオブジェクトで保持 | 地形、所有国、施設、座標は型付き列。可変属性のみJSON系 | 5桁固定長と255・65535由来の上限を継承しない |
| 所有者 | 順位番号をセルに埋め、順位変化時に再割当 | 島マップは実質的に島所有 | 不変のnation_idをセルへ参照 | 順位を識別子にすると再配置・破損リスクがある |
| 国家登録 | 希望中心座標の周囲を調査し、初期領土を造成 | 外部認証後、独立島をランダム生成 | 空き領域をサーバーが探索し、首都と初期領土を原子的に配置 | 利用者任意座標だけに依存せず、競合時の再試行が必要 |
| 初期資産 | 資金100、食料100、村・森・山・基地など | 資金3000、食料10万、資源5万、人口2000 | 設定・rulesetで管理し、バランス試験後に確定 | どちらの数値もそのまま採用しない |
| 世界拡張 | なし。固定配列 | なし。島サイズ固定 | 必要時に上下左右へチャンク境界単位で最小拡張 | 既存座標の移動や全マップ再生成は禁止 |
| 座標 | 共有世界のx、y。六角隣接は列の偶奇依存 | 15×15のx、y。表示も固定サイズ前提 | signed axial q、rを正本とし、pointy-top odd-qはUI投影だけに使用 | 配列添字を恒久IDとして扱わない |
| ターン入口 | CGI・管理操作に近い入口から全世界更新 | Artisanコマンドからサービスを呼び、DBトランザクション | Schedulerから専用Application Serviceを起動 | Webアクセス起点や多重実行可能な入口は避ける |
| ターン順序 | 国境、収支、先頭命令、全セル、難民、災害、集計、保存 | 維持費、生産、国内命令、他島命令、災害、セル処理、集計、保存 | 明示したフェーズパイプラインとruleset版で管理 | 巨大関数の暗黙順序に依存しない |
| コマンド | 固定配列キュー、1ターン原則1命令 | plans JSON、国内・国外コマンドを分離 | 正規化したcommand_queueと状態遷移、対象検証、冪等キー | JSON配列全書換えと巨大switchを避ける |
| 地形・施設 | 数値IDとswitch、配列に広くハードコード | Terrain Entity、定数・クラス群だが分岐が散在 | カタログID、振る舞いサービス、データ駆動設定を併用 | DBだけで任意コードを実行する過度な汎用化もしない |
| 災害 | 世界・セル単位の確率分岐 | Disaster系Entityでセルに適用 | フェーズ、対象集合、確率、結果イベントを分離 | 呼出順で確率が変わる不透明な乱数消費を避ける |
| 怪獣 | 共有世界のセル上を移動・攻撃 | 島内のセルイベント | 地上レイヤーの位置を持つ主体として将来設計 | 初期リリース範囲は別途決定 |
| ミサイル | 共有座標を攻撃、種類ごとの分岐 | 他島コマンドとして対象島・座標を指定 | world_id、map_space_id、q、rで対象化し、命中・防御をイベント化 | 相手島IDを空間の代用にしない |
| 国境 | 周辺影響でセル所有者が変化 | 国境概念なし | 隣接影響、抵抗、占領条件を独立ルール化 | 首都を通常の占領対象にはしない |
| ログ | 表示用文字列をファイルへ保存 | 67種のログクラスが表示断片JSONを生成 | 構造化domain_eventを正本、表示文は投影 | HTML断片を永続データの正本にしない |
| 認証 | 平文パスワードを含む旧式CGI | Google・Yahoo等の外部認証、Sanctum | Laravel標準認証境界と外部IdP連携を候補化 | 平文秘密、デバッグ認証、本番用IdP固定は不可 |
| UI | 世界全体をJavaScriptへ埋め込む | Blade初期データ＋Vue、225画像を一括描画 | 首都周辺を初期取得し、スクロール方向のチャンクを遅延取得 | 全世界送信、15列固定CSS、セルごとの線形検索を避ける |
| API | CGIフォーム中心 | 認証付き6ルート、他島マップは全量 | バージョン付きJSON API、チャンクETag、カーソルページング | 画面用HTML断片をAPI契約にしない |
| 管理 | config.cgiと管理操作 | 専用管理画面は見当たらない | ruleset公開、ターン監視、障害復旧、監査を管理機能にする | 設定変更とコードデプロイを常に同一にしない |
| 設定 | config.cgiに多数、残りはC定数 | 多くがPHPコードへ埋込み | DB ruleset＋環境設定＋秘密管理を責務分離 | 認証秘密や接続情報をDBルールへ入れない |
| 排他制御 | ファイルロックがあるが保証に疑義 | トランザクションはあるがターン多重起動ロックなし | 世界単位の排他ロック、実行ID、冪等性を採用 | トランザクションだけで二重実行は防げない |
| 原子性 | 複数ファイルで非原子的 | 主要保存はDBトランザクション | 1ターンの論理境界をDBトランザクションとoutboxで保証 | 外部通知をトランザクション成功条件に含めない |
| 乱数 | 秒単位シードのC乱数 | 実行環境の非決定的乱数 | turn_runごとの記録可能なseedと用途別乱数ストリーム | 再現不能な障害解析を避ける |
| テスト | 実質なし | Controller中心とターン成功例が少数 | ドメイン単体、フェーズ統合、再現seed、API契約、負荷試験 | HTTP成功だけでルール正当性を証明しない |
| Docker・運用 | 旧CGI環境を手作業設置 | app、DB、frontend等のCompose、Cloud Run例 | 開発環境はコンテナ候補。Web、worker、schedulerを分離 | 既存Composeを変更・流用せず、Phase 2では起動もしない |
| バックアップ | 世代バックアップの仕組みあり | 明示的なアプリバックアップなし | DB継続バックアップ、復旧演習、turn_run単位の監査 | アプリ内コピーだけを唯一の復旧策にしない |
| 拡張性 | 固定上限、switch、グローバル配列 | クラス分割はあるが島・15×15前提が浸透 | bounded context、カタログ、modifier、layerで追加可能にする | 汎用EAVで型安全性と検索性を失わない |
| ライセンス・画像 | 原本条件と作者表示を尊重。原GIF 58個を確認 | リポジトリ直下LICENSEなし。画像95点の条件不明 | コードは独立実装。箱庭諸島2＋の原GIFだけをGit外・read-only配置から実行時使用し、Creditsを表示 | 画像バイナリをGit収録・独自素材として再配布しない。やまにてぃ画像へ同方針を拡張しない |

## 結論

新作は、箱庭諸島2＋から「同じ地表を複数国家が共有し、国境が動く」というゲーム上の核を残し、やまにてぃから「Laravel、ドメイン概念のクラス化、DBトランザクション、Vueによる操作画面」という実装上の方向性を参考にする。ただし、両実装の固定サイズ、全量処理、表示断片保存、識別子の不安定さは継承しない。
