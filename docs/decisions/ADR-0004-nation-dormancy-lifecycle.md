# ADR-0004 国家休眠ライフサイクル

- 状態: 採用
- 日付: 2026-07-26
- 対象: 国家状態、ターン対象、領土占領、放棄、復帰、地図からの退去

## 文脈

共有世界で長期間活動しない国家を永続的な不可侵領域にすると、新規登録と国境変化を妨げる。一方、短期休眠で直ちに資産を失わせたり、国家・ユーザー・履歴を物理削除したりすると、復帰可能性と監査性を損なう。

首都は通常の災害・攻撃・占領では消滅せず、人口も最低1単位を保つため、人口0を国家削除条件にできない。活動時間に基づく段階的な状態遷移を正本とする。

## Decision

国家の排他的なlifecycle stateは次の4つに統一する。

- active
- dormant_frozen
- dormant_contestable
- sunken_archived

新規保護はstateではなく期限付きpolicyまたは属性として扱う。defeated、dormant、archived等の別名を国家stateとして併用しない。

UTCの評価時刻がlast_active_atから次の期間へ到達した瞬間に状態を変える。

| 無活動期間 | 状態 |
|---|---|
| 30日未満 | active |
| 30日以上180日未満 | dormant_frozen |
| 180日以上365日未満 | dormant_contestable |
| 365日以上 | sunken_archived |

明示的放棄は365日を待たずsunken_archived相当の沈没処理を開始する。

## active

- 資源生産・消費、人口変化、災害、ランダムイベントを実行する。
- 怪獣、通常攻撃、国境、領土の通常ルールを適用する。
- 通常commandを登録・実行できる。

## dormant_frozen

30日到達時に移行する。

- 資金、食料、人口、各種資源を変動させない。
- 生産、消費、災害、ランダムイベント、村の自然発生、自動発展を停止する。
- 新しい怪獣を発生させない。既存怪獣の移動・破壊も停止する。
- 通常の国境侵食を停止する。
- 首都を含む全領土を占領不能とする。
- 一般攻撃の対象にしない。

例外として、既存怪獣の排除を目的とする明示的な怪獣討伐ミサイルだけを許可する。着弾対象は実行時点で怪獣が存在するセルに限る。逸れた先が怪獣セルでなければ被害なしの失敗とし、施設、人口、地形、所有権へ影響させない。通常ミサイルhandlerを流用して副被害を出さず、怪獣へのdamageだけを許可する専用policyで検証する。

## dormant_contestable

180日到達時に移行する。

- 資源・人口の凍結、生産・消費・災害・ランダムイベント・自動発展の停止を継続する。
- 首都以外の領土は、専用の占領・領土変更ルールで他国が取得できる。
- 首都セルの所有権と首都施設は保護する。
- 占領済み領土は本人がactiveへ復帰しても自動返還しない。
- 過去領土と現在領土を履歴上で区別する。
- dormant_frozenと同じ怪獣討伐専用ミサイルの例外を継続する。

一般攻撃を全面的に再開する決定ではない。少なくとも通常の人口・施設damage commandは凍結を破らない。占領に必要な抵抗処理、防壁施設、首都周辺をどこまで占領可能にするかは未決定である。

## sunken_archived

365日到達または明示的放棄の沈没処理完了時に移行する。

地図上では次を行う。

- 残存領土の地形を海へ戻し、所有者を解除する。
- 首都セルと首都施設を地図上から除去して海へ戻す。
- 設置施設を除去する。
- 現在地図上の領土と首都を持たない状態にする。

次は物理削除しない。

- userとauth identity
- nation
- event履歴と状態遷移履歴
- 称号
- 過去統計とranking履歴
- 過去の領土・首都履歴
- 監査記録

現在資源・人口の生産や消費は行わない。保持する残高を再入植でどう扱うかは未決定であり、自動的に初期資源へ加算しない。

## 復帰

365日未満で本人が有効なログイン、ゲーム画面利用、命令登録、または明示的な復帰操作を行うとactiveへ戻す。

- dormant_contestable中に他国へ移った領土を自動返還しない。
- 残存領土と、残っている首都から再開する。
- 凍結期間中の生産、消費、人口変化を遡及計算しない。
- 停止turn分の資源やログインボーナスを一括付与しない。
- 復帰者保護はstateと分離した期限付きpolicyとして別途決める。

sunken_archivedからは直接activeへ戻さない。旧領土を巻き戻さず、空き領域探索を使う再入植を基本候補とする。

## 活動時刻

状態判定の正本はUTCのlast_active_atである。表示時だけAsia/Tokyoへ変換する。ターン数や単純なsession存続を正本にしない。

last_active_atを更新する候補:

- 本人による対話的な認証完了。
- 認証済みゲーム画面の明示的利用。
- 命令登録・変更。
- 明示的な復帰操作。

background polling、token refresh、残存session、外部通知閲覧だけでは更新しない。高頻度画面操作は一定時間に1回へ書込みをまとめてもよいが、意味上の最新活動時刻を失わない。

## 状態遷移の実行

Schedulerが専用LifecycleEvaluationJobを定期投入する。JobはUTC nowとlast_active_atから目標stateを導出し、同じ国家へ複数回実行しても同じ結果になる。

状態変更では次を同じ整合性境界に記録する。

- nation_id
- before_state、after_state
- reason
- evaluated_at、effective_at
- last_active_at
- actor。systemまたはadmin/user
- idempotency key
- domain event

ターン処理と地図変更の競合を避けるため、world lockと共通のchunk lock順を使う。turnのFreeze後にstateを途中変更せず、どちらか一方を待たせる。

## 365日沈没処理

小規模なら地図変更とstate変更を1 transactionで確定する。大規模領土でtransactionが過大になる場合は、内部のlifecycle_transition_operationを使う。

1. nationごとに一意なtarget stateとreasonを持つoperationを作る。
2. 対象worldのturn・領土更新を排他し、国家操作を停止する。
3. 所有chunkを安定順で処理し、各chunk checkpointを保存する。
4. 「まだ当該nationが所有するセル」だけを海・ownerなしへ冪等更新する。
5. 全chunk、首都、施設の処理完了を検証する。
6. 最終transactionでnationをsunken_archivedへ変え、eventを確定する。

途中失敗時は完了checkpointを飛ばし、残りを再実行する。operationのprocessing状態は内部処理状態であり、5番目の国家lifecycle stateにはしない。

## 明示的放棄

本人の放棄はsunken_archivedへの理由付きtransitionとして扱う。乗っ取り・誤操作対策として、再認証、国家名等の確認入力、待機期間、取消期間、管理ログ、重要eventを実装前に決める。管理者による例外変更もbefore/after、理由、actorを監査する。

## 結果

### 利点

- 短期休眠者を保護しつつ、長期放置領土を段階的に共有世界へ戻せる。
- 国家・ユーザー・歴史を削除せず復帰と監査ができる。
- UTC時刻で判定するためturn間隔変更の影響を受けない。

### 欠点

- turn、占領、沈没cleanupの排他が必要になる。
- dormant_contestableの占領ルールと首都周辺範囲を追加決定する必要がある。
- 大量領土の沈没にはcheckpointと再試行設計が必要になる。

## 未決定事項

- dormant_contestableで首都周辺の何ringまで保護するか。
- 防壁等の抵抗を占領時に残すか、無効化するか。
- 復帰者保護の期間と対象行為。
- sunken_archivedからの初期資源、旧国家名、nation identity、ranking、保護期間。
- 明示的放棄の待機・取消期間。
- 沈没時の希少itemと将来の地下・宇宙資産の扱い。
