# 4.14.0 地底・夕凪の帰港地の背景と解禁イベント・狂月賛歌の準備

## 実装範囲

- 試練3初回クリア後、既存の狩場4名「夕凪の帰港地」でホーム背景を選べる。狩場の解禁条件・戦闘・報酬は既存のまま。
- 地底ホームで「④更なる深層へ」を表示する。本文はOwner提供の原文を使用し、`(秘書名)`だけを文字列として補間する。
- 読み終え操作は既存のイベントAPI、profile lock、request admission・idempotencyを使用する。Secretary所有profileの`yunagi_harbor_intro_completed_at`に既読を保存し、再訪やreceipt整理後にも初回イベントを再表示しない。
- イベントは透明な鏡の購入を問わず表示する。案内人は既存ショップが鏡の有無に応じて解決した立ち絵の分岐をそのまま再利用し、画像・配置・権利表記を共有する。
- 背景を`ai_generated`として登録する。非AI設定では背景URLを出さず、既存の水晶背景へ戻す。選択済みの背景キーは保持する。

## 適用時の作業

`2026_10_04_020000_add_yunagi_harbor_intro_completion.php`はnullableの既読日時を追加する。既存の試練3クリア済みSecretaryにも、次の地底ホーム訪問でイベントを表示する。

画像`resources/scene-assets/background/4140-yunagi-harbor.jpeg`はOwnerの添付JPEGを加工せず収録したもの（1536×864、418,903 bytes）。SHA-256は`d911168e4659a19d8d0cfeaa280b228bc8149c3b3ea9c1258d98ca6af372db66`。

本番へ適用する場合は、既存の素材更新手順に従って背景と`scene-assets.json`を配信先へ配置してからアプリを更新する。PR作成時点ではmerge、deploy、本番画像配置、migration適用を行わない。

## 狂月賛歌の非公開準備

Owner提供の「●狂月賛歌」と撃破後の「●メム＝リリム」を原文のまま別JSONに保存した。撃破後本文には末尾の追記を含み、`|呪い《ギフト》`も保持する。ルビは既存の`renderUndergroundStory`で安全に表示できる。本文以外のキャラクター原作設定は収録しない。

既存のintro catalogに通常勝利50回の条件と本文を登録し、`prepareMadMoonIntroduction`は既存`UndergroundContentClearProgress`の`hunting_ground / yunagi_harbor / actual_clear_count`を読み取る。新しい勝利数のauthorityは作らず、過去の通常勝利を継承する。本文の`(秘書名)`だけを文字列置換し、案内人表示は既存ショップの鏡分岐からそのまま再利用する。メムの立ち絵はOwner添付を加工せず収録し、指定の権利表記を使用する。

この準備処理は通常state、イベントAPI、frontendの導入口には接続していない。戦闘・決算が完成するまでプレイヤーに公開しない。勝利後シーンの一回表示・既読保存も、実際の勝利確定処理と合わせて接続する。

接続時は、4.13.0までに試練3をクリア済みなら次の地底ホーム訪問で④を表示する。港町で通常勝利50回に既に到達していれば次の港町の通常戦闘終了後に狂月賛歌を起動し、50回へ初到達する場合はその勝利の確定後に起動する。条件成立済みの次回戦闘は勝利に限定しない。スキップを起動契機にせず、導入後の50勝のやり直しや移行時の完了扱いをしない。

戦闘は既存PT combatを再利用する方針。既存レンタルPTの設定を保存したまま、この戦闘だけ案内人と秘書の2人で戦う。秘書の実際の成長・装備を使用し、案内人は覚醒なし、秘書がタンクならアタッカー、それ以外ならタンク。案内人はLv1000・IL220相当へ約15%加算し、覚醒を持たない。秘書のLv1000・IL220・覚醒MAXは調整目安で、初戦でも勝利できる設計とする。

通常戦からの連戦は前後のHP・覚醒をそのまま引き継ぐ。撤退・敗北後に限り狩場一覧へ「狂月賛歌」を表示し、再挑戦できる。勝利後は再戦できず、撃破後本文を一度表示する。勝利報酬は中級バハムル1（`bahamul_intermediate_1`）のEXPとGの量だけを参照し、現行値はEXP 200,000・G 120,000。共鳴結晶などのitem dropは付与しない。

バランス測定はLv1000・IL220・覚醒MAXを目安に複数seedで行い、32/32勝利のような全勝結果を適正と判定しない。初戦で勝てる可能性を残した上で、少なくとも1回の敗北を含む強さへ調整する。測定結果を満たすための強制敗北は入れない。戦闘の数値定義・測定はまだ未実施。

連戦の戦闘消費、通常戦敗北後のHP 0からの開始扱い、再挑戦時のHP・覚醒は未指定。敗北後の独自本文は追加しない。戦闘・NPC snapshot保存・決算・一回表示への接続は未実装。

## 検証

既読の恒久保持・試練3クリア条件・AI表示設定・鏡購入条件をbackendのfocused確認で検証する。frontendはホーム限定表示、文字列補間、読み終え配線、再読込後の非表示を確認する。

狂月賛歌の準備は通常勝利49/50回の境界、スキップ数との分離、過去進行の参照、無消費、導入口の非公開をfocused確認する。
