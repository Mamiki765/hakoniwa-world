# 5.7.0 怪獣図鑑・地上アイテム図鑑

Owner依頼（2026-10-21）。秘書メニューに「図鑑」を足し、怪獣と地上アイテムを集める楽しみと、拾った品の最大Lvなどを読める場所を作る。仕様の決定は Owner と 2026-10-21 に確定。載せ先は `release/5.7.0`。

application **5.7.0 / Ruleset v41**。リリース全体の統合・検証と本番適用の境界は[5.7.0リリース記録](5.7.0.md)を参照する。

## 変更する挙動

- 図鑑はプレイヤー（user）単位。島を作り直しても登録と受け取り済みは残る。
- 怪獣: 自分の島（島主の島）の攻撃で怪獣のHPが1以上実際に減った時に登録する（`MonsterDamageService::applyDamage`）。硬化・迎撃でHPが減らなかった時、出現しただけ、派遣しただけは登録しない。
- 地上アイテム: 秘書の倉庫に品が入った時に登録する。入口は `SecretaryItemGrantService`（ドロップ・宝・チケット・合成・配布・最初の古びた弓）と交易場の受け渡し（`TradingPostTurnService`）。
- 未登録の項目は「？？？」で、アイテムは分類とレアリティの色だけ、怪獣は出現の目安だけを見せる。名前とkeyは返さない。
- 登録した項目は最大Lv・合成上限・最大Lvの効果文・フレーバー・売値・交易場に出せるか・初めて手に入れた日（怪獣は体力・経験値・出現・特性・初めてHPを減らしたターン）を見せる。マニュアルに載っている範囲を超える内部情報は出さない。
- 項目ごとの「プレゼント」で 5Pd、怪獣とアイテムを合わせた登録数 10個ごとに 20Pd。どちらも1回だけ。「まとめて受け取る」で全部受け取れる。未受取がある時は秘書メニューの図鑑タブと見出しの秘書ボタンに赤丸。
- API: `GET /api/v1/me/secretary/collection`、`POST /api/v1/me/secretary/collection/claim`（`kind: monster|item|bonus`、`key`）、`POST /api/v1/me/secretary/collection/claim-all`。`GET /api/v1/me/secretary` に `collection.unclaimed` を足す。

## 分類と版

登録は乱数もゲーム状態も読まず、行を「なければ作る」だけなので、同じ版・同じシードのターン結果は変わらない。金額（5Pd・10個ごと20Pd）は `SecretaryCollectionService` の定数で、Ruleset は変更しない（版上げなし）。

forward migration `2026_10_21_000000_add_user_collections.php`:

- `user_collection_entries`（user_id, kind, entry_key, source=live/backfill, first_turn, registered_at, claimed_at）、`(user_id, kind, entry_key)` 一意。

## 公開時の運用（過去分を埋める）

順番は、デプロイ → `php artisan migrate --force`（この版の migration で表ができる）→ 下の `--dry-run` で件数を見る（オプション省略時も dry-run）→ Owner が件数を確認してから `--apply`。本PRでは本番で流さない。表ができる前に流すとテーブルが無くて止まるので、必ず migration の後に流す。公開から `--apply` までの間にプレイで登録された項目と受取状態は保持する。記録にあるターン・時刻の方が古ければ、`first_turn`（初めてHPを減らしたターン）と `registered_at`（初回登録日時）をそれぞれ古い方へ戻す。放棄された島は、作った人が1人に決まる時だけその人へ付け替える。

```
php artisan hakoniwa:backfill-collections --dry-run   # 件数だけ見る
php artisan hakoniwa:backfill-collections --apply     # 書き込む（何度流しても同じ）
```

材料: 討伐記録 `nation_monster_kill_stats`、残っている `monster.damaged` / `monster.killed`（与えたHPが1以上）、今持っている品、売却記録、チケットの結果と使い切ったチケット、合成の記録（固定レシピは材料も）、災害で使い切ったお守りの記録、交易場の出品と落札。島の持ち主へ付け替える。「初めて手に入れた日」は記録に残る一番古い時刻（入手・売却・チケット・合成・出品や落札・討伐記録・攻撃記録）を使い、無ければ流した時刻になる。消えた記録の分は次に出会った時に登録される。埋めた項目は「登録済み・未受取」になる。
