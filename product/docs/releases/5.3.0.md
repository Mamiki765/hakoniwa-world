# 5.3.0

application version は **5.3.0**。本番使用済み v37 を `N` とし、エコポの v38 を同じ `N+1` の1世代として使う。v37 の payload・checksum と既存 migration は変更しない。

## 統合内容

- #276: 難民受入の人口反映を既存の共通処理へ集約する。
- #277: 港の隣接条件を計画登録と実行で共通化する。
- #279: Ruleset 更新前から生存する怪獣を引き続き Turn の対象にする。出現時の定義と履歴を保ち、新しい討伐統計は現在の World catalog に記録する。怪獣と船の占有分離を維持する。
- #280: 上限超過で最終的に失われた資源・確定収益を島所有のエコポへ換算し、Turn 末に1,000万点ごとに1Pdへ交換する。端数は島に残す。売却分・消費分・保持資産・未送付の援助・未受取補填を加算せず、資産・ポイント・Pd・audit は同じ transaction で扱う。本人の島 API に整数 `ecopo` を返し、公開 API には出さない。詳細は[エコポ](../architecture/ecopo.md)を正本とする。
- #281: 本人の「収支と資源」→「島のあらまし」に残高を表示し、交換ログの助詞を修正する。公開島表示には追加しない。

## 移行

追加する forward migration は次の2本。今回の版整合では追加・変更しない。

- `2026_10_15_000000_add_nation_ecopo.php`: `nations.ecopo` を非負の BIGINT として追加し、0点で開始する。
- `2026_10_15_010000_publish_ecopo_ruleset.php`: v38 を公開し、v37 の World と queued command の実行定義を更新する。元の request identity と既存資産を保ち、未解決の公式 Turn がある場合は拒否する。

fresh install は既存の v37 公開を経て v38 へ進む。旧版怪獣の履歴・出現定義、船の provenance を付け替えない。過去分の遡及配布はこの release の適用に含めず、調査・preview と実付与は別判断にする。

## 検証と適用境界

各 PR の exact-head Quality CI と Codex review の結果は各 PR を正本とする。版表示の整合だけを理由に Codex 再 review を要求しない。#281 と版整合 #282 は `release/5.3.0` の `14399e95a6da80168d8c09c33b9b562d0fc720e4` へ統合済み。ローカル候補統合とこの確定 SHA の source tree が完全一致することを確認した。

確認済みの証拠:

- #281 の head `b6e7e1ab0ea5ce5e24e5d2bb7016a5417f0a18d6` は [Quality CI](https://github.com/Mamiki765/hakoniwa-world/actions/runs/38729044627) 成功、[Codex review](https://github.com/Mamiki765/hakoniwa-world/pull/281#issuecomment-6201744029) は重大指摘なし。#282 の版・文書 head `c53ec1a8afedcbc25e26a94ddb332eb512e35da2` も [Quality CI 全22 jobs](https://github.com/Mamiki765/hakoniwa-world/actions/runs/38729071590) 成功。最終統合 source の CI はこの2つの PR head の結果とは区別して確認する。
- #281 の CI 実行ログで、PostgreSQL 上の `EcopoSettlementTest`、`EcopoUpgradeTest`、`FreshInstallRebaselineTest`、`DatabaseBaselineAdoptionTest`、`LivingMonsterRulesetUpgradeTest`、`SurfaceCommandAndAidExecutionTest`、`UnderseaConstructionShipUpgradeTest` の実行と各 shard の成功を確認した。最終破棄だけの付与、本人 API と公開 API の境界、Pd の端数・一意性・rollback、fresh/upgrade、資産・queued request identity の保持と未解決 Turn の拒否、旧版怪獣と船の占有分離を既存テストが検証する。
- 確定 source tree でローカルの型検査と既存 frontend 2 files / 36 tests が成功。一時的なモック API 確認で、本人の残高0点表示、Turn 更新の API 再取得による12,345,678点への反映、公開プレビューに残高を出さないことを確認した。確認用のテストファイルは削除し、恒久テストは追加していない。

残る最小の確認は、稼働する隔離 PHP/PostgreSQL 環境で既存のエコポ・移行・旧版怪獣の focused tests を実行し、同じ検証 DB の本人 API 残高と画面、Turn 末の交換ログと Pd/端数を照合すること。repository-wide suite をローカルで重複実行せず、最終統合 source の Quality CI を適用前に確認する。

これはリリース準備の記録であり、本番 deploy・DB 更新・backup 完了の証拠ではない。本番適用は確定 SHA と同期結果を照合し、既存の backup・preflight・通常 deploy 手順に従う。
