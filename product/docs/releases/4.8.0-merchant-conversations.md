# 4.8.0 行商人と話す

交流場に「行商人と話す」タブを追加する。交流場の導入を読み終えた後、既存の背景・アキの立ち絵の下で、一問一答の談話を読める。導入文と初期2題「キミは誰？」「輝石のかけらをなぜ集める？」はOwner提供の文章をそのまま収録する。

## プレイヤーの操作

- 初めは質問のみを一覧表示し、回答をすべて閉じる。
- 質問を押すとその回答が開き、同じ質問を押すと閉じる。複数の回答を開ける。
- 他のタブへ移って戻ると、回答は閉じた状態へ戻り、最新の表示中の話題を取得する。
- ブラウザ標準の `details` / `summary` でキーボードでも開閉できる。回答の改行を保ち、plain textとして表示する。
- 読込失敗時は画面内で再取得できる。表示中の話題がないときは空の案内を表示する。

## 管理人の追加・編集

管理ページの「行商人の会話」を開く。リカの `GuideConversationTopicAdmin` を共用し、アキでは質問・回答・表示するチェックだけを使う。登録・更新・削除は既存と同じ操作で、質問は1,000文字、回答は4,000文字までのplain text。回答は3行程度を目安に改行を入力する。非表示の話題も管理一覧に残り、再編集できる。

既存のDiscord IDによる管理者認可を使い、一般プレイヤーは登録・更新・削除できない。追加・編集にbuildやreleaseは不要。プレイヤーは次にタブを開いた時に最新内容を読む。一覧は登録順で、題数を固定する制限は設けない。

## 保存と初期導入

新しい `merchant_conversation_topics` に質問・回答・表示状態と、作成／更新の管理者・日時を保存する。初期2題はforward-only migration `2026_09_30_010000_add_merchant_conversation_topics` が一度だけ登録し、以後の正本はDBとする。初期登録の管理者IDはnullで、架空の管理Userを作らない。既存の話題やplayer dataを書き換えない。

導入文だけは既存の物語ファイル `resources/stories/lounge.json` に置く。初期回答をruntimeのfallbackや二重のdefinitionとして保持せず、管理画面の編集を後日のbuildで上書きしない。

公開用の認証必須GET `/api/v1/me/underground/merchant-conversation-topics` は表示中のID・質問・回答だけを返す。管理用CRUDは `/api/v1/admin/merchant-conversation-topics`。回答を開閉する操作は画面内で完結し、会話受付・RNG・報酬・閲覧記録を増やさない。リカの会話契約とRulesetは維持し、application versionは4.8.0とする。

## 確認

既存の管理画面・地底表示の代表テストとfrontendの型検査・lint・buildで接続を確認する。追加のAPI代表1件で管理者認可、plain text validation、登録・更新・非表示・削除、player向けprojectionを確認する。既存のリカ用テストが行商人用routeと表示filterを検証しないため、この独立した失敗条件を追加する。

PC・狭い画面の実ブラウザでクリック・キーボード開閉、タブ再入場、回答の折り返しと管理画面の登録・編集を確認する。ローカル表示には一時的なfixture APIを使う。ローカルのPHPとDocker daemonは利用できないため、backend・migrationの実行とrepository-wide PHPUnitは最終HEADのQuality CIで確認する。
