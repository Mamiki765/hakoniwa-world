# 地上アイテム拡張：Relic・合成・育成アイデア帳

原案：2026-09-28。後続決定の照合：2026-10-19、`release/5.5.1` の `93bb230b8cff546e43d1b89baf4c7cd916ff616f`。分類：**5.5.0で採用済みの範囲と、残る構想・未決事項**。本番適用の確認ではなく、このメモを根拠に未採用案をRulesetへ追加しない。

この文書は、今後増える地上アイテム案を忘れないための常設メモ。4.6地下装備の一時開始資料とは別で、地上アイテム案を継続して追記する。実装時は現行code、Ruleset、Open gateを再確認し、このメモだけをcurrent runtime contractにしない。

## 0. 後続決定：5.5.0で採用・実装した範囲

- 本人の秘書画面に合成UIを実装。対象は同種お守り5種・チケット2種のLv合算9999までと、夢魔の紋章の固定レシピ。弓・衣服の同系統育成や自由な効果合成は含めない。
- serverが素材IDと土台IDを選び、POST時に同じ集合を再検証する。装備中土台を優先し、Lv9999の装備中土台から未装備同士へ自動fallbackしない。取引預託中の素材を除外し、固定レシピ素材は未装備に限る。装備version・未解決Turn guard・transaction・結果snapshotによる再送を維持する。
- 通常入手の`max_level`と合成後の`synthesis_level_cap`を分離した。チケットは回数指定の部分使用に対応し、消滅するチケット1枠を含めた倉庫容量と回数付き再送内容を検証する。
- 夢魔は三紋章各Lv1の無料固定合成、成果物Lv1、自然回復・誘致の人口増加+100%、プレイヤー交易可・NPC出品不可・通常ガチャ対象外。素材を満たす合成候補とレシピ内容をUIに表示する。
- 地上倉庫は100Pdで+50、最大250。通常入手・付与の経路にも購入済み拡張を反映する。

根拠は[5.5.0採用記録](../releases/5.5.0-market-synthesis.md)、`config/hakoniwa/rulesets/v40/secretary.php`、`SecretarySynthesisService`、`SecretaryTicketGachaService`と`SecretaryItemGrantService`。以下の原案で「未決」とした項目は、この採用範囲だけ後続決定で解決している。それ以外の構想の承認にはならない。プレイヤー向けマニュアルへ掲載する範囲は別のOwner判断であり、合成UIの実装から推定しない。

## 1. Relic

- 地上アイテムの上位rarityとして**Relic（レリック）**を使う。Artifactより上。
- 固定売値は**6,000億**。
- Relicは将来的にドキドキチケットから約1%程度で出る案があるが、**主な入手は合成**にする方向。
- 一部の例外Relicはタグ/分類でチケット排出対象外にする。合成限定・隠し系を想定。
- 2026-09-28時点では、ドキドキチケットから排出する具体的Relicはまだ考えない。まずRegular / HQ / Artifact以下の地上アイテムを増やす。
- 現行のドキドキチケット排出率やRelic排出率を、この構想だけを理由に今すぐ変更しない。

## 2. 合成の目的

合成は主に次の二つを狙う。

1. **ダブった地上アイテムの消化・育成**
2. **複数の既存効果を、作者定義の固定レシピで上位rarityへ圧縮するやり込み**

「任意の効果AとBを自由にmergeする汎用効果合成」は作らない方向。効果圧縮も**固定レシピの拡張**として扱う。

将来、複数効果をまとめたRelicを作る場合、素材側の効果を最大限引き継ぐには、弓や衣服のように素材自身を同系統アイテムで育てておくことが重要になる構想。完成品だけ拾って即最大性能になるとは限らない。

ただし、すべての固定レシピに素材Lv継承を要求するわけではない。レシピごとに決める。

## 3. 同系統アイテムの修行・Lv育成

弓やスーツは上位rarityが強く、下位rankが入手後に空気になりやすい。そのため、下位rankや同系統のダブりを上位品へ食わせ、Lvを上げる仕組みを検討する。

例として考えている方向：

- Artifactの任意の弓を育てるため、同系統のHQ / Regular弓を素材にする。
- 1rank下をどの程度の確定成長にするか、2rank下を「複数枚まとめて昇格素材にする」「低確率で1rank上へ変える」「rarityごとの固定経験値にする」等は未決。
- 同種/同系列の育成量を単純な+1/+2にするか、経験値方式にするかも未決。
- 将来の合算Relicでは、素材弓・素材衣服の育成度が継承効果量へ影響する案を残す。

目的は「下位レアを引いたら完全なハズレ」を減らし、Regular → HQ → Artifact → Relicへ長期的な価値を繋ぐこと。

## 4. 固定レシピと効果圧縮

効果圧縮は固定レシピで定義する。

例：

- 農場+20%系アイテム + 工場+15%系アイテム
- → 将来の固定レシピRelicとして、農場/工場の複合効果を持つ
- 基本イメージは低い側に揃えて農場+15% / 工場+15%のように圧縮する案

ただし将来、素材Lv/育成度を継承率へ使う場合は、最大値を引き継ぐために素材を先に育てる必要がある。

この数値・継承式・対象カテゴリはまだ未決。固定レシピごとに決める。

## 5. 夢魔の三紋章 / 夢魔の紋章

### 素材

- 愛の紋章
- 双子星の紋章
- 三日月の紋章

三つとも**Lv1固定のArtifact**。それぞれ自体がレアなアイテムであり、三つ揃えること自体を入手難度とする。弓のような素材育成・Lv継承は要求しない。

「夢魔の三紋章」は三つをまとめる概念上のタグ/グループ名として扱う構想。実装keyやUI表記を今ここで固定しない。

### 固定レシピ

```text
愛の紋章
+ 双子星の紋章
+ 三日月の紋章
= 夢魔の紋章
```

### 夢魔の紋章

- rarity：Relic
- Lv：**1固定**
- 入手：**合成限定の隠しアイテム**。ドキドキチケット等の通常排出から除外する方向。
- 効果：**自然回復と誘致活動での人口増加が2倍**
- フレーバー：
  - 「人間よ、快楽だけを貪る獣に帰れ。もう何も暗い事を考えなくて良い様に。」
- 三つのレア素材を揃えることが難度なので、完成後の素材育成条件は付けない。
- 2026-09-28の原案では、入手を急がず三素材の存在から「何かある」と示唆することを狙い、公開時期・開示方法・合成UIは未決だった。
- 後続の5.5.0で無料固定合成とUI表示を採用した（0節）。原案の「未決」を理由に現行レシピを隠したり撤去したりしない。

## 6. 同種圧縮

同じアイテム同士を重ね、倉庫を圧縮する用途も合成へ含める。

### チケット

```text
わくわくチケット LvA
+ わくわくチケット LvB
= わくわくチケット Lv(A+B)
```

- Lv合算を主用途にする。
- 2026-09-28時点では、一部アイテムだけ通常max_levelを超える仕組みを候補とし、チケット・お守り等への適用範囲、合成上限、UI、使用時の処理は未決だった。
- 5.5.0で5種お守り・2種チケットの同一key合算、上限9999、合成UIとチケット部分使用を採用した（0節）。他の品や同系列の異なるkeyへ拡大する判断は含まない。

通常入手のチケットmax_levelは1のまま、合成後は9999まで保持できる。使用時は残Lv以内の回数を指定し、全消費か部分消費かで受取容量を判定する。旧「max_levelが1なので高Lvは使わない」という読み方へ戻さない。

## 7. 原案の判断項目と残る範囲

合成UI、transaction / retry / idempotency、装備中・取引中の素材、通常上限と保持上限の分離、夢魔の取引可否・排出除外、v40追加と既存instance保持は、0節の限定範囲で5.5.0に実装した。以下は原案の確認項目として残す。弓・衣服育成など対象外の新レシピへ適用するときには改めて決定する。

- 合成UIの置き場所と解禁条件
- 合成時のtransaction / retry / idempotency
- 素材が装備中・取引中・escrow中の場合の扱い
- 同系統育成の対象関係（同一key / 同カテゴリ / 定義済み系譜）
- 1rank下・2rank下の育成量
- 素材Lvを固定レシピ完成品へどう継承するか
- 通常max_levelと合成上限突破を同じ値で持つか分離するか
- Relicのドキドキチケット排出率・具体的な排出対象（今は決めない）
- 合成限定タグ/排出除外の表現方法
- 合成結果の売値・tradable/npc_tradable
- Ruleset versioningと既存アイテムinstanceの保持

## 8. 2026-09-28時点の確認メモ（履歴）

2026-09-28のmain確認では、地上CatalogにRelic rarityと固定売値6000億は既に存在する。三紋章もArtifact / Lv1として存在する。現行ドキドキチケットはHQ / Artifactのみで、Relic排出枠はまだない。

この時点の観測は保持し、後続の夢魔固定合成は0節を参照する。数値を永久固定するテストの根拠にしない。
