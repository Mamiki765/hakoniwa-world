# H：異世界バトル／黒竜バハムル blueprint（仮）

2026-09-22／未実装の設計。基点 `8060bb0572d2de737c4b9516e3b2c9c22b55e835`。Ownerのボス像を、実装する順序と比較条件へ整理する。**世界共有HPレイドではない。HP・攻撃倍率・勝率をシミュレーション済みとはしない。**

## 1. 固定したいOwnerの意図

固定PTで挑む高難易度。人数によって敵の強さを補正しない。戦技2・防御1・回復1を調整の基準とし、技は4〜5種類を持つ。HP閾値の大予告からメガフレアなどを放つ。前段階の装備と別軸強化を集めて次に挑む。

| 段階 | 調整用Lv | 仮の報酬IL | 比較装備・強化 |
|---|---:|---:|---|
| 初級1 | 100 | 130 | 狩場3を50勝程度。既存品と導入段階の強化。サイド強化の入口はG案で確認 |
| 初級2 | 200 | 150 | 初級1装備がある程度＋一段下の強化 |
| 初級3 | 400 | 180 | 初級2装備＋一段下の強化 |
| 中級1 | 666 | 210 | 女王に勝てる編成程度＋初級3装備／強化 |

Lvは入場制限ではなく調整用fixture。少人数で挑戦したら敵が弱くなることはない。レベル上限へ同期させる新ルールも依頼されていない。高Lvになって少人数攻略できる余地を残す。

## 2. 技の仮構成

最初の黒竜は以下の4技、上位から5技目を加える案。単なる通常攻撃名の付替えで4種類と数えず、対象・対処が違う行動として作る。

| 技（仮名） | 役割 | 対処・戦闘での意味 |
|---|---|---|
| **黒爪** | 単体への重い物理攻撃 | 挑発・防御役で受ける意味を作る |
| **黒炎の息吹** | 全体への魔法攻撃 | 全体回復と魔法側の軽減を使わせる |
| **竜翼** | 全体への比較的軽い物理攻撃＋短い攻撃低下候補 | 回復だけでなく攻撃再開のタイミングを作る。新statusが不要なら既存debuffを使う |
| **メガフレア** | HP閾値で予告して放つ大技 | 予告後に防御・barrier・回復を挟める。単にログだけ出して即発射しない |
| **深淵の咆哮** | 上位段階の自己強化など | 5種類目。効果を一つに絞り、解除・耐久・火力の選択を作る |

名称・効果・採用順は提案。バハムートに似た題材でも他ゲームの画像・音・専用台詞・複雑な戦闘式を複製する提案ではない。

## 3. 予告の処理境界

推奨は、HP閾値を初めて越えた行動終了でbattle内の`charging`を立て、**少なくとも次の一巡をプレイヤー側が対処に使える**ようにすること。具体例は、予告したroundの次roundを準備時間にして、その次のボス行動で発射する。敏捷差によって予告直後に即発射しない。

閾値・発射済み・保留大技は一戦のruntime stateに置き、再戦へ持ち越さない。準備中に撃破されたら取り消す。女王の「HP1で耐えて必ず2回目の奥義」の契約を自動コピーしない。発動閾値と通常行動が重なった時の優先順位も一箇所で決める。

AIはプレイヤーの手動反射操作ではなく、既存の防御・barrier・回復actionで対応する。現行AIが敵の予告状態を条件として参照できるかを実装時に確認し、未対応なら必要な条件一つを小さく追加する候補とする。名前がchargingなだけでAIが読めると仮定しない。

## 4. 戦闘から決算まで

```text
異世界一覧 → 段階／ボスの説明 → PTと消費条件を確認
    → 借用元の短期snapshot
    → 自分のprofileをlockし受付・入場条件再確認
    → 固定ボス入力を既存pure combatへ
    → 結果・コスト・報酬・clear事実を一度だけ確定
    → 履歴と報酬画面
```

既存の`UndergroundRuntimeService`、借用factory、canonical combat engine、装備drop・loadoutへつなぐ。違いはボスの入力・行動選択・報酬・受付契約として局所化し、通常探索と平行の独立engineを作らない。

人数による補正なしは、敵のHP/能力だけでなく敵数でも守る。通常探索の「PT人数分の敵」を流用してボスを4匹にしない。報酬も通常探索の人数平均処理を惰性で通さず、ボス定義の1戦の報酬として意味を決める。

通常のtrialはsolo、女王決闘は無料・通常報酬なしという既存の差を保持する。異世界へどちらの決算を流用するかだけで結果を決めない。本人の通常HP/MP/覚醒を持ち込むか、戦闘後どう戻すか、貸出参加報酬・日課対象かは未決事項として明記してから実装する。

入場は10分待機または歪んだ輝石の消費。両方必須にしない。通常狩場の10秒待機とは別。失敗時の消費と練習のしやすさはOwner確認対象。入場料を払ったあとに一時的エラーが出ただけで取り直しを要求しない。

## 5. 装備の伸びを確認する順序

現在の生成上限・body/売価anchorは120までで、割合affixのIL倍率は101以降で上限。IL150と表示するだけでは強くならない。HQの枠数とレリックの枠数も違うので、旧理想品との比較が必要という既存調査を引継ぐ。

まず役割ごとに、Lv200・同じ他部位・同じAI・同じサイド強化で、理想IL120武器と初級2の実用的なHQ武器を差し替えて比べる。平均的な良品で更新できることを目標にし、IL150の最高rollユニークだけが勝つ設計にはしない。

その後、4段階のfixtureで倒せる／対策すると改善する／旧装備だけでは苦しい、を少数の共通seed群で比較する。勝率の一点やseed番号を永久的なgameplay契約にしない。まず初級1一体を縦に通し、技が意図どおり動くかと報酬処理を確認してから4段階へ広げる。

報酬はOwner案のHQ以上と、時折の竜武器ユニーク。Gの良品竜晶が入る場合は独立の小さいdrop枠にする案。確率と通常報酬の量は未採用。初回clearや解禁は恒久progress、装備／竜晶はprofile所有資産、詳細battleは期限付きというDの寿命境界を守る。

## 6. 実装を始める時の小さい順序

1. 既存combatとボス入力の接続、固定強度、4技と予告の行動機会を確認する。まだ本番の入場を開けない。
2. IL130/150の曲線と竜武器1種を比較する。G方式の採用が未決ならサイド強化なしの比較値も残す。
3. 受付・コスト・決算・初回clear・既存履歴に接続する。未決の経済値は採用前に確認する。
4. 初級1を試遊し、同じ経路のdataとして残りの難易度を追加する。専用engineや専用transactionを難易度別に複製しない。

本書は設計であり、勝率・適正HP・全装備IL曲線を算定した結果ではない。コードの変更点が明らかになったところだけfocusedを選び、全技×全状態×全人数の巨大matrixを先に作らない。
