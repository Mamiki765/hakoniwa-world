4人PT想定の固定強度。人数に応じて弱くしない。初級は通常予告からメガフレア、中級は深淵の咆哮から5→4→3→2→1、次roundの敵行動で強化メガフレア。大予告は1で立ち、発射までのAI判定に使う。咆哮は対象の覚醒ゲージを補充するが、自動覚醒にはしない。専用「着弾済み」AI条件はOwner却下済み。

勝利時に黒竜晶1個確定、ユニーク武器は勝利ごと10%。4武器種から選択。結晶は熾牙（might）・堅鱗（guard）・命脈（healing）・慧眼（finesse）の4種で、能力配分が異なる。黒竜晶の固有効果は共通の範囲攻撃強化。種別ごとに固有効果を勝手に変えない。

4.4.1で異世界全段階の初回勝利日時の恒久保存・既存receiptからのbackfillと、初級1/中級1の公開トロフィーを追加した。古い予定表を理由に初回記録を再配布・再生成しない。

### 共鳴結晶・研磨・IL200超の装備

専用装備1枠・通常装備と別倉庫。ボス固有効果とランダム効果2枠を持ち、同じランダム効果が重複してよい。

研磨は最大＋5、成功率100%、再抽選・破壊なし。固定能力は＋0値の30%を1段階ごとに加算。割合系は基準値へ1段階10bps（0.1 percentage point）を加え、rating対象は研磨後の基準値を品のIL倍率で投影する。**この4.6対応は実装済みで、追加の「研磨量再設計」は未完TODOではない。** 固有固定%まで一律にIL倍率化しない。

`S(IL)=1.1^(max(0,IL-200)/10)`。IL210=1.10、IL220=1.21。武器力は出力倍率、防具はHP倍率。旧武器加算値を内部で維持する。ratingの必要倍率は `S(max(200,min(武器IL,防具IL)))`、防具未装備はIL200相当。IL210石のランダムaffixとその研磨増分は×1.1でrating化するが、実効%は要求側倍率で割る。従って「装備にかかわらず常に実効＋10%」ではない。

攻撃・能力/固定量由来回復・障壁への武器倍率と、割合回復・吸収への二重適用禁止を区別する。最大HP affixは各品のILで一度だけ加算し、防具倍率で二重拡大しない。防御行動強化の実効減算上限90%は、既存の別系統の軽減capを置換しない。物防/魔防特化防具はOwnerが見送っており、この倍率対応に混ぜない。

計算の正本は[地底装備の倍率とrating](../architecture/underground-equipment-scaling.md)と実装。共鳴結晶の確認付き個別売却、貸出・覚醒・戦闘・画面のrating/実効値への接続は4.6で実装済み。

宝物庫増築(1)は通常装備500→600、共鳴結晶庫増築(1)は50→100。従来確認値はいずれも1,000,000G。値そのものを永久固定するテストの根拠にはしない。

### データ・運用

User → Secretary → UndergroundProfileの所有関係を維持。島破棄で秘書や地底進行を消さない。

## B. 統合handoffから維持する実行・所有契約

### 永続情報・再送・統計

装備のsource identityと出所CHECKは保持し、削除可能receiptへのlive FKとは分離する。既存装備を再抽選・再配布しない。貸出参加累計と初回growth/tutorial/Trialの事実は恒久側へ保存し、respecから初回選択を推測しない。

統計は恒久rollupとverified境界より後のrawを同じSQL snapshotで読む。purgeは検証済みprefixに限定し、pin・進行中・恒久事実不足で停止する。全request IDの無限台帳、月別bucket、30日超rawの別名コピーを追加しない。

新規mutation受付はserver生成のUUID・profile・HTTP operation・issued/expires/versionを結び付けた24時間。期限後の既存結果再読取と、未知／削除済みrequestの再実行を混同しない。入口とprofile lock後の確認を維持する。

本人damageの根拠がない旧PT記録は0でなくNULL/incomplete。最大一撃は1行動・1対象で、敏捷連撃は合算し、AoEの別対象を合算しない。覚醒変身の全快と、覚醒技による実回復を分ける。日誌は探索・試練・力試し・初回tutorialを含み、命名storyと案内人決闘を除く。

### Turn・管理操作

C1の再試行は同一起動のtransaction本体の対象競合に限定し、rollback、同run/target/ruleset/seed、PHP状態再構成を守る。World lockを取得したwrite PDOを維持し、接続変更を再取得で迂回しない。[lock境界](../architecture/secretary-lock-boundaries.md)と実装を正本にする。

配布は受取Userを正本とし、確認時の対象を実行時に増やさない。島がない場合もUser資産を扱い、地上資産は現在の島と容量に応じて残額を倉庫へ保持する。島整理は既存の競売決算・地上整理・公開ニュース・auditを接続し、User/秘書/地下進行を削除しない。[管理運用](../operations/4.4.0-admin-operations.md)を参照。

### 女王決闘・貸出・表示

女王決闘は通常探索と別決算。通常HP/MP/覚醒/G/EXP/cooldown/貸出参加/日課へ結果を戻さない。初勝利グラムは一度だけの装備・売却不可記念品。初勝利後のソロ再戦は実際のPTが空のとき会話を差し替え、誘導選択肢を増やさない。

成長方針とskillは別軸。借用更新時はHP全快・覚醒0、その後は持ち越し、宿はHPのみ。地底表示は16:9、AI OFFでは非AI placeholder、creditは素材単位。小さな表示修正でこれらの意味を変えない。通常能力は装備込み、STP配分は裸ステを維持する。

### 地上と地底の境界

地底攻略の地上還元は首都地下の施設群。新しい地上産業・電力・属性魔力を、地底攻略が必須の仕組みへ勝手に拡張しない。今後の地底新システムを原則狩場3で解禁したいという方向は構想帳に保持し、既存の例外を一律移動する指示とはしない。

### 同期

GitHub→Forgejoはmain・一階層release/*・tagの片方向同期。force・削除・逆同期をしない。同期成功とproduction反映を分け、remoteやupstream、credentialを推測・記録しない。Ownerが明示したreleaseだけを作成する。
