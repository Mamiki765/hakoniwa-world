# 箱庭諸島2＋と新作構想の差分

## 結論

旧版から残す価値が高いのは、共通世界、六角近傍、ターンフェイズ、予約コマンド、国家と領土の関係、イベントログという **ゲーム上の概念** である。固定配列、順位owner、5桁セル、平文ファイル、グローバル状態、CGI埋込みJavaScriptという実現方法は持ち込まない。

## 構想別ギャップ

| 新作構想 | 旧C実装 | 差分・必要な設計 |
| --- | --- | --- |
| 初期60×60の共通世界 | `worldSize=60` の単一共有マップ | 数値と共有概念は一致。ただし旧版は「初期」ではなく永続固定サイズ（`config.cgi:43-44`; `map.c:13-47`） |
| 必要に応じた縦横の自動拡張 | なし | 拡張条件、方向、単位、最大範囲、同時拡張lockが新規に必要 |
| 既存座標を移動しない世界拡張 | なし。配列添字が座標 | 不変の世界座標とchunk座標を導入し、原点再配置をしない設計が必要 |
| チャンク単位保存 | `map.cgi` 一括 | chunk key、境界近傍読込、版、原子的更新、空chunk表現が必要 |
| スクロールに応じた部分取得 | 全60行を `mapData` として毎回出力 | viewport + margin、ページング/streaming、権限別秘匿変換が必要（`Map::jsOut`, `map.c:50-67`） |
| 国家作成時に首都を自動配置 | 利用者が中心座標を指定。首都施設なし | 空地探索と予約、首都セル/エンティティ、初期領土templateを新設（`new_island.c:50-209`） |
| 首都施設は消滅・占領しない | 通常施設は災害・攻撃・感化対象 | 不変性を通常セルswitchの例外ではなくドメイン不変条件にする |
| 首都人口は割合減少 | 町は全損または絶対値減少 | 被害種別ごとの割合、丸め、同一turn複数被害順を定義 |
| 首都人口の最低保証 | なし。人口0で国家消滅 | 最低値、復帰条件、国家消滅との関係を定義 |
| 防壁都市による国境抵抗 | 防衛施設はミサイル迎撃のみ。国境は隣接1セルのownerへ即変更 | 抵抗値、攻撃/圧力、継続turn、占領条件、首都との関係を新設（`map.c:211-260,479-489`） |
| 災害率とターン間隔の設定化 | 既に `config.cgi` で設定可能 | 概念は継承。値域、適用開始turn、履歴、管理権限、再現性を追加（`config.cgi:52-107`; `value.c:125-160`） |
| 将来の地下・宇宙マップ | 単一2D地表だけ | layer/world ID、層間移動、各層の境界・災害・可視性を新設 |
| 後付け資源・施設・研究・熟練度・アイテム効果 | ID、費用、効果が多数のswitch/配列へ分散 | 定義データ、効果component、条件式、versioned rule set、migration機構が必要 |

## 残すべき挙動

### そのままではなく、仕様として抽出して残す

1. **全国家が同じ世界を共有すること**：一つのセルに一つの地形・所有者があり、国家間相互作用が直接起こる（`Map::land`, `map.c:3`; `Land.owner`, `map.h:171-173`）。
2. **六角形の距離と同心範囲**：配置、災害、攻撃、難民に共通の距離概念がある（`map.c:5-10,69-85,1200-1224`）。
3. **予約コマンド**：将来行動をキューに入れ、turnごとに処理する（`command.c:62-103,110-117`）。
4. **フェイズ順**：国境、収支、コマンド、セル、災害、集計、消滅、保存を分ける（`Turn::main`, `turn.c:9-148`）。順序そのものは新仕様テストで再承認する。
5. **実行順の偏り軽減**：国家・セル順をshuffleする考え方（`turn.c:151-198`）。新作ではseedを記録する。
6. **地形と所有者の分離**：海上油田・海底基地、中立荒地等を表せる。ただし所有者は不変IDへ変える。
7. **施設と周辺地形の相互作用**：森の防火/防風、防衛施設の迎撃等（`map.c:479-489,840-982`）。
8. **出来事のログ**：公開/当事国限定の区別を含む（`hako_io.h:70-76`; `hako_io.c:488-504`）。現代のイベントモデルへ置換する。
9. **バックアップと復旧の運用概念**：方式は捨てるが、定期snapshotと管理者復旧は残す。

## 持ち込むべきでない旧設計

| 旧設計 | 問題 | 置換方向 |
| --- | --- | --- |
| 可変人口順位をセルownerに保存 | 毎turn全セル変換、参照不安定 | 不変国家ID |
| 1 byte `owner/param` と5桁セル | 255上限、型安全・拡張性なし | 型付きschema、十分な整数幅、制約 |
| 全世界1配列・1ファイル | 動的拡張・部分取得不可 | chunk repository |
| 全セル毎turn走査 | 世界拡大に比例して重くなる | active chunk/event scheduling、集約処理 |
| その場更新 + 乱数順 | 再現困難、順序依存 | 明示snapshot/phase、記録seed、event result |
| CGIアクセスがturnを進める | アクセス量とゲーム進行が結合 | scheduler/workerとidempotent turn |
| 秒単位seed | 再現・監査不可 | turnごとの保存seed/PRNG state |
| 平文password/Cookieへ再出力 | 機密性がない | 認証基盤、hash、session |
| 非原子的な複数ファイル上書き | 部分更新・破損 | transaction/atomic commit |
| `flock` のグローバルlock | 実装不具合候補、水平拡張不可 | DB transaction、lease、idempotency |
| switchと配列への規則直書き | 追加機能が横断変更 | versioned rule registry/components |
| Shift_JISバイト処理 | Unicode非対応 | UTF-8とUnicode単位の検証 |
| HTML内JavaScriptデータ | XSS、全件転送、API分離なし | JSON API/typed DTO/viewport取得 |
| 設定値の無検証読込 | 0除算・巨大確保等の危険 | typed configuration validation |
| 消滅国の全領土を即時海化 | 歴史・廃墟・占領概念を失う | 新作の国家消滅/中立化規則を別途定義 |

## 推奨する境界

新作では少なくとも次を別責務にする。これは実装開始ではなく、旧版との差分から導く設計要件である。

- `WorldCoordinate` / `HexDistance`：無限または拡張可能な不変座標。
- `Chunk` / `ChunkRepository`：部分保存・取得・境界近傍。
- `Nation`：不変ID、資源、研究、熟練度、inventory。
- `Territory`：所有と争奪状態。順位と切り離す。
- `Capital`：不変施設、人口最低保証、攻撃時割合被害。
- `FacilityDefinition` / `Effect`：施設IDと後付け効果。
- `TurnPlan` / `TurnResult`：フェイズ、seed、入力snapshot、結果event。
- `RuleSet`：災害率、費用、生産、上限の版管理。
- `WorldLayer`：地表・地下・宇宙を同じ座標APIで区別。

## 移行時にデータ変換が必要な旧前提

旧データを将来取り込む場合、`owner` 順位をその時点の `info.cgi` 配列から不変 `Island.id` へ解決してから保存する必要がある（`Info::getIsland`, `info.c:116-122`; `Land::changeOwner`, `map.c:1368-1374`）。`param` は地形ごとに意味が異なるため、kindごとの型付き値へ展開する。中心座標は首都ではないため、旧 `centerX/Y` を自動的に首都へ昇格させず、移行規則を別途決める。
