# 5.8.3 休眠島のお守り消費によるターン停止を修正

application **5.8.3 / Ruleset v41**。5.8.2のmain `12a4f242028e4d0bd8b8db118097762c4214b264` を基準にする緊急修正。本書はコードの範囲を示し、本番への適用完了を意味しない。

## 原因と修正

2026-10-28 22:00 JST、1008ターンの`finalize_turn`で`Secretary charm usage references an item outside the turn-start snapshot.`が発生した。ターン全体がrollbackされ、Worldは1007ターンに留まった。失敗後のcronは既存のmanual retry契約により再試行しない。

お守りの開始時snapshotはactive・dormant・recoveryの島を対象にする一方、消費の確定処理はactive・recoveryだけを走査していた。休眠島の首都保護範囲外でお守りを使うと、snapshotにある正当な消費まで不正として拒否していた。

`SecretaryTurnService::flushCharmCharges()`の走査対象を、開始時と同じ`lifecycleNationIds()`に揃える。残数・所有者・装備slot・装備versionの検証と、消費の一括保存を維持する。

## 検証対象

休眠島の首都保護範囲外で津波が発生し、防波のお守りを使う実際の全ターン処理をregressionに追加する。ターン完了、施設の保護、お守り残数、装備versionを確認する。既存のお守りrollback・retry用fixtureにも本来のlifecycle対象を設定する。

Ruleset snapshot・世代、DB構造、migration、依存は変更しない。自動retryや失敗runの書換え・削除を追加しない。本番の更新と1008ターンの手動retryは、Ownerの別途指示で既存run・target turn・Ruleset・seedを維持して扱う。

最終HEADの検証結果とCIはリリースPRに記録する。
