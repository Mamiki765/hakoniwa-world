# 4.1.1 問い合わせのロックとスキル説明のテーマ修正

## 対象と原因

4.1.0 main `a06fbf8bafdb8769ecfcb510a8ac3a6f9eb9da52`を起点とするhotfix。2026-09-14のOwner依頼に基づき、INQ-000008の可読性と、Turn・地下PT履歴・問い合わせのロック共存を修正する。

問い合わせはUserを`FOR UPDATE`で保持してから、World／Nationを参照する問い合わせ行を挿入していた。TurnがWorld／Nationを保持してSecretaryを待ち、地下PTがSecretaryを保持して借用者Userへの外部キー参照を待つと、次の循環が成立する。

```text
Turn: World/Nation保持 → Secretary待ち
地下PT: Secretary保持 → 問い合わせが保持するUser待ち
問い合わせ: User保持 → Turnが保持するWorld/Nation待ち
```

本番調査報告だけでは最後の待機対象がWorldかNationかは断定できない。隔離PostgreSQLで実際の外部キーを使った再現では、Nationへの`FOR KEY SHARE`で待つ三者デッドロック（SQLSTATE 40P01）を確認した。犠牲transactionは本番報告ではTurn、再現では問い合わせだった。

## 修正

- `InquirySubmissionService`のUserロックだけを`FOR NO KEY UPDATE`へ変更する。同一Userの問い合わせは引き続き直列化し、地下PTの外部キーによる`FOR KEY SHARE`を妨げない。[PostgreSQLのロック競合表](https://www.postgresql.org/docs/18/explicit-locking.html#LOCKING-ROWS)に対応する。
- `UndergroundSkillTree.vue`のスキル説明に、既存テーマ変数の文字色・背景色・枠色を指定する。操作案内の文字色も既存の補助文字色へ合わせる。固定の暗い背景にライトテーマの暗い文字色が継承される不整合を解消する。
- application versionを4.1.1にする。

地下・問い合わせをターン中に拒否するguardは追加しない。問い合わせの外部キー確認などがTurn終了を待つ場合は引き続きある。即時応答やロック待ちゼロを保証する変更ではない。

Turnのatomicity、Secretaryのロック順、問い合わせの冪等性・添付失敗時の削除・自動再実行しない契約は維持する。migration、Ruleset、戦闘仕様・係数、保存データの変更はない。

## オプションの関連経路

Ownerの追加懸念に合わせ、現在のコードを確認した。

- ライト／ダーク切替は`App.vue`のCookieとDOM更新だけで、DBへ保存しない。
- コメント・島主名変更は`NationProfileService`で最初にWorld、続いてNationをロックする。Userを先に保持してWorldを待つ今回の循環は作らない。Turn終了まで保存が待つ場合はある。
- 休止・島破棄は既存の`WorldMutationLock`と未解決Turn guardを維持する。

これらの経路にはコード変更を加えない。全操作を網羅したデッドロック不存在の証明ではない。

## focused validation

PostgreSQL 18.4の隔離DBで、現行schemaの外部キーと別接続のworkerを使用した。worker間の進行は標準入出力で制御し、`pg_blocking_pids`で待機を観測してから次へ進める。sleepの偶然によって競合を起こす方式ではない。

- 修正前：新規の三者並行regressionが40P01で失敗することを確認。
- 修正後：同じregressionで三者とも完了。実際の`InquirySubmissionService`とPT memberの外部キーを使用する。Turn／PT workerは関連するロック・保存区間を再現するものであり、TurnRunner全phaseや戦闘全体のE2Eではない。
- 同一User・同一submission keyの並行送信：問い合わせ1件・添付1個。片方だけが新規作成を返す。
- `InquiryConcurrencyFailureTest`＋`InquiryApiTest`：11 tests / 99 assertions成功。既存の添付削除・DB失敗時に自動再試行しない確認も含む。
- frontend：`App.test.ts`の地下画面、テーマオプション、案内人の代表3 tests成功（filterで44件中3件を選択）。
- PHPStan（変更service）、Pint（変更PHP 5 files）、VueのESLint、typecheck、frontend build、`git diff --check`成功。
- 実際のスキルcomponentと共通CSSを使ったfixtureをブラウザで表示。375pxのlight／dark／systemと1280pxのlightを確認し、文字の可読性と横方向のはみ出しなしを確認。ログイン済みの本番画面E2Eではない。

PHPのfocused commandは、接続先が隔離PostgreSQLであることを確認したtesting設定で実行する。

```sh
php vendor/bin/phpunit -c <isolated-testing-config> tests/Feature/InquiryConcurrencyFailureTest.php tests/Feature/InquiryApiTest.php
npm run test -- --run resources/js/App.test.ts -t 'shows the unlocked Underground projection|opens theme options|opens the Guide room'
npm run typecheck
npm run build
```

全PHPUnit・全frontend suiteは実行していない。本作業では本番DB操作・Turn再実行・merge・deployを行わない。
