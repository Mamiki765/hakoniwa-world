# 地上発展拡張：配置・電力・二次三次産業・属性魔力

更新：2026-09-30。分類：**Ownerの構想・採用方向と未決事項**。未実装であり、次releaseへ自動追加しない。会話中のAssistantによる実装例は、Ownerの決定と分けて記録する。

## 1. Ownerが求めている発展

人口と基礎施設を増やすだけでなく、成熟した島の土地・労働人口・資源を効率よく使う発展を作りたい。上位の二次・三次産業は、原則として普通に人口を増やして生産するより費用対効果を高くする。ランキング・名声・景観を狙うものは、経済効率が低くてもよい。

新要素の候補は、施設合体によるrank-up、施設上限と災害耐性、複数マス施設、4マスで5マス分・6マスで8マス分という集約、配置による生産効率化。どれか一つへ確定したわけではない。

## 2. 五つの資源から上位品を作る

Ownerの構想：

```text
人口・基礎施設 → 作物 / 工業品 / 鉱物
油田           → 原油
発電設備       → 電力（新しい系統）

この5系統を材料に、高付加価値な上位品や上位産業へ進む
```

既存の保存key・単位をこの略図だけでrenameしない。各産業が何種類の資源を消費するか、加工品を独立在庫にするか、その場で売上へ変えるか、電力の保存方式は未決。

Assistantが出した食品加工、精密機器、特殊合金、石油化学、港を利用した観光等は**検討例**。施設名・原料比率・収益・最初に実装する種類まで採用済みと扱わない。

## 3. 配置を考えて効率化する面白さ

Ownerが挙げたRAの例は、単なる高収益施設ではなく**海あみゅフォーメーション**。また、大農場が森・銀行とつながり、一つの支援施設を複数施設で共有する効率のよい配置の画像も提示した。

意図は、同じ施設数でも種類・位置・距離・共有の仕方によって効率が変わり、島の盤面を考えることが攻略になること。RAの特定の形・施設数・倍率をそのまま2S＋の固定レシピにする決定ではない。

比較中の方式：

- 独立した施設のまま、隣接・範囲条件で効率を上げる。
- 同種または指定した組合せを合体させてrank-upする。
- 複数HEXを占める大型施設にする。
- 土地効率や施設上限を上げ、災害耐性などを付ける。

4→5相当・6→8相当はOwnerが出した規模感の例。自動合体かコマンドによる合体か、一部損壊時にどうするかは未決。「区画IDを新設する」等はAssistant案で、先行実装しない。座標や形は現行の6近傍を持つ地図に合わせ、通常の正方形盤面の十字/2×2を無条件に持ち込まない。

## 4. 電力

Ownerは電力を五つ目の基盤として検討したい。発電方式・原料・供給単位・貯蔵は未決。

比較候補は、毎ターンの供給/需要容量、備蓄資源、蓄電施設がある場合だけ貯蔵する方式。原油火力、バイオマス、風力・潮力等はAssistantの候補であり、採用済みではない。

「まず上位産業だけ電力を必要とし、既存の農場・工場を突然停止させない」という案もAssistantの導入案。現行仕様やOwner確定条件と混同しない。

## 5. 地底との境界

Ownerが明示した地底RPGの地上への報酬は、**首都地下に建てる施設群**。

この新しい地上産業の構想から、地底攻略専用通貨や必須素材を勝手に追加しない。地底の既存施設が基礎産業へ与えている効果と、地上の新産業をどう接続するかは、実装時に現行契約を確認する。

会話に別途あった「地上→地底の還元」候補は逆方向の話で、具体的内容は未決。これを「新しい地上産業は地底攻略必須」という決定へ読み替えない。

## 6. 属性魔力とエルフ秘書の奇跡

Ownerの意図は、属性魔力を高めて奇跡を起こすような箱庭の発展を作り、エルフ秘書を地上でも活躍させること。地底の戦闘skillだけを拡充する話ではない。

魔力の発生源を自然・地形・属性石・施設のどれにするか、電力と同種か別種か、属性数、恒常効果と発動型の違いは未決。豊穣、防災、再生、航行、鉱脈活性化、結界等はAssistantの具体例。秘書の力を使うために地下Lvや攻略を必須とする決定はない。

## 7. 実装前に調べること・決めること

| 項目 | 状態 |
|---|---|
| 現行資源の生産・消費・売却・上限・UIの経路 | 現行codeで確認する。会話で実装前調査プロンプトを提示したが、実行完了報告は未確認 |
| 電力の保存方式と発電方式 | Owner判断待ち |
| 上位品を在庫にするか、加工収益にするか | Owner判断待ち |
| 最初の産業、原料比率、投資費、収益 | Owner判断待ち。食品加工が第一弾と確定したわけではない |
| 配置条件と共有効果、合体方式との併用 | Owner判断待ち |
| 災害耐性の位置づけ | 主効果/副効果とも未決 |
| 属性魔力の仕組みと秘書の介在 | Owner判断待ち |

実装では現行のTurn順序・資源上限・保存/決算・6近傍helperを確認する。巨大な汎用産業engineや新schemaを、未決仕様のために先行して作る許可ではない。
