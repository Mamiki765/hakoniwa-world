# 4.4.0 migration統合

2026-09-23、未適用の`release/4.4.0`（`5c6977b27b2dd2786e3d41f2fef8f2a6935a72fc`）にある17本のmigrationを`2026_09_23_030000_install_4_4_0.php`へ統合した。4.3.2以前のmigrationとschema dumpは変更しない。

## Productionの起点

読み取り専用で確認したproduction checkoutは`3f49819fb764b5ac2e9fc49f95f6795ded7754d2`（4.3.2）だった。migration台帳の最新行は`2026_09_18_000000_allow_configured_trial_reward_lengths`（batch 42）で、4.4.0の17本は未適用だった。統合migrationはこのpre-4.4.0 schemaからの更新を対象にする。中間draft schemaを検出した場合は書込前に停止する。

## 統合内容

秘書の経験値と装備version、貸出累計、導入と試練の初回事実のbackfillを維持する。receipt rollupは4.3.2に存在しないため最終形で作成し、中間draftのrollup再集計は移さない。案内人・輝石購入・研磨を含むrequest operation CHECKを一度で構築する。装備のprovenanceと報酬一意制約、管理系、異世界、個人記念碑、ガチャ履歴を含め、最後に既存の`Ver440RulesetUpgrade`でv27を有効化する。`down()`はforward-onlyとする。

## 検証

隔離したPostgreSQL 18.4の2つのDBを4.3.2 schemaから構築し、同一の秘書・地上装備・地下進行・券残高をseedした。旧17本と統合1本の適用はどちらも成功した。2つの`pg_dump --schema-only`はランダムな識別子行を除いて一致した。秘書の経験値123、装備version 7、装備、地下EXP 17・shard 83・banked 29、券残高12とv27設定digestも一致した。migration台帳は旧経路17行、統合経路1行だった。

別の隔離DBでv27公開時に意図的なDBエラーを起こしたところ、統合migrationは失敗し、追加テーブル・v27・台帳行は残らず、秘書の旧2列と値が保持された。

fresh installと代表PHPUnit 5件（87 assertions）、変更PHP 6ファイルのPintと構文確認、`git diff --check`が成功した。4.3.2データ入り更新の回帰テストを`Release440MigrationTest`に残した。repository-wideの最終判定はPRのexact-head CIで確認する。

本番migration・deploy・PR mergeはこの作業に含めない。
