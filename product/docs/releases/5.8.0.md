# 5.8.0 予約ブーストと永続ターン実行枠

Owner の「次のminor」指示により、main の application 5.7.0 に続く5.8.0として実装する。基準は `ae98c3d81823bf948987016f42253a2d7a786396`。作業branchからmain向けDraft PRを作り、本番操作・実イベント予約・マージはしない。PHP・Dockerfile・Composer依存の更新を含めない。

時間加速は大規模障害補填だけに使う単発予約。通常12ターン=箱庭歴1年=実時間1日を維持し、お祭り用途へ広げない。開始・終了、追加上限1〜500回を指定し、期間内の先頭N個のJST奇数時00分を保存する。期間は最大31日で、指定回数が入らなければ409。追加だけで120分、通常偶数時00分と合わせて追加枠のある間は1時間ごとの予定になる。テスト例の日曜09:00〜23:00・7回は09 / 11 / 13 / 15 / 17 / 19 / 21時。短い18:00〜23:00へ7回を詰める案は廃止し、実予約前に時間帯か回数の判断を要する。

通常の `hakoniwa:turn:run --source=cron` は既存JST偶数時00分cronを維持し、補填予約・未補填数と無関係に通常枠だけを実行する。補填は新しい `hakoniwa:turn:compensate` と `product/docker/cron/run-compensation-turn.sh` をJST奇数時00分cronで単発起動する。毎分pollや常駐workerは追加しない。追加受付は予定の00分内（起動秒のずれ59秒まで）だけ。01分以降・偶数・未予約・期間外・上限後・未補填ゼロは無変更で終了する。

未補填枠と実行時刻をターン番号から切り離して永続化し、両commandと手動更新でWorld lock・一意な実行枠を共用する。完了記録とゲーム決算は同じtransactionで、1起動最大1ターン。失効枠の遡及・自動再配置・未解決失敗の自動retry・無制限catch-upを行わない。追加回数は成功保証ではなく上限。

狩場ブーストは再利用可能なお祭り用途。レア出現率2倍・通常敵の鍵出現率2倍・XP2倍、確率100%上限、レア確定鍵の数量・G・他報酬は維持する。単独/PT/単独skip/一括skipへ受付時snapshotを渡す。試練・宝物庫・異世界・イベントには波及させない。

イベントの種別と固定倍率は今回Ownerが確定した操作の意味で、任意倍率の別catalogを導入しない。開催日時と有限繰り返しは運用データ。既存Ruleset v41と既存snapshotを変更せず、Ruleset世代は増やさない。予約・実行枠・通常枠カーソルを追加するforward migrationは隔離DBでのみ検証する。

公開・管理API、開催回の識別・取消、JST/UTC、プレビューの形式と制限は[API契約](../architecture/boost-scheduling-api.md)、通常/補填それぞれのcron起動と移行上の境界は[運用手順](../operations/turn-scheduler-worker.md)を参照。補填側12回/日と既存通常12回/日を想定するが、起動回数だけで本番負荷を断言しない。旧毎分案の計測値は参考履歴で、新commandは未計測。

## UIとの統合

サーバー・管理室はDraft [#334](https://github.com/Mamiki765/hakoniwa-world/pull/334)、公開帯は別Draft [#332](https://github.com/Mamiki765/hakoniwa-world/pull/332)、画面側の最新確認HEADは `de775082e63d2c8d79c8071f9ca1a6376c310102`。Gitの実コードでTOPの「停止補填中：追加ターンあり（未補填分のみ）」を確認し、旧「60分ごと」の残件は解消済み。TOP・島・地底の帯を重複実装しない。

公開APIは種別ごとに開催中または次の開催回を1件返し、管理APIで全予約（最新500回）を確認する。管理室フォームはJST日時・時間加速の上限・狩場の毎日/毎週・プレビュー・確認予約・開催回/以後系列の取消を扱う。時間加速の送信は開始/終了/追加上限で、間隔を入力・送信しない。APIでは `interval_minutes` は省略または120のみ、他は422。旧省略helperは維持する。実際の追加時刻全件と未補填数による実効上限を表示する。「遅延ターン分」は未補填N・開始から2N時間を入力し、開始を次の奇数時00分へ揃える補助で、自動予約しない。両PRはmain向けの別PRのままとし、どちらも本タスクではマージしない。

公開の `turn_interval_minutes` とpreviewの `interval_minutes` は追加だけの120分固定で、無条件の成功間隔を保証しない。次回表示は `next_scheduled_turn_at` を正本にする。effectsには追加上限と保存時刻一覧を返し、帯のdescriptionは大規模障害補填・奇数時00分・上限・未補填条件を示す。#332の汎用TOPは適合し、固定60分コメントとeffects明示型の追随が残る。新commandを含む最終統合はPR本文で追跡する。具体的な所属は[画面連携の引継ぎ](../architecture/boost-ui-integration.md)に記録する。

## 残る判断

- 宝物庫そのもののXPを狩場ブーストに含めるかは未決。現実装では含めない。
- 長期停止で未補填基準を再開時刻へ変更するか、歴史的な遅延を別記録にするかは未決。現実装は既存カーソルを維持し、明示上限だけ新規予約する。
- 失効した追加枠を残期間へ再配置するか、別予約で補填するかは未決。現実装は再配置しない。
- 日曜の実予約日時と停止終了時刻は未確定。本番には一切予約しない。
- 本番 migration、補填側ホストcronの登録、公開再開は別途のOwner判断。通常cronは維持し、今回の再開作業では本番操作・実予約・DB変更・cleanupを行わない。
- Fastを指定する正式なsetterを確認できず、Fastは未設定。別モデルへの変更をFast利用とは扱わない。
